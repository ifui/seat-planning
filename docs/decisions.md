# 技术决策记录（ADR）

> 记录本项目已经做出、且会长期影响维护方式的关键决定。
> 每条包含：背景 → 选项 → 结论 → 代价。日期以迭代轮次表示。

---

## ADR-01 交付形态：Vite + `vite-plugin-singlefile` 单 HTML

**背景**
使用场景是双击 HTML 离线排座，不能依赖服务器、内网地址或安装包。

**选项**
1. 纯手写单文件（无构建）—— 没有组件化、类型检查，代码量上千行后不可维护；
2. Vite 构建 + 手动内联资源 —— 多一步脚本，容易漏资源；
3. Vite + `vite-plugin-singlefile`；
4. Electron/桌面壳 —— 体积与分发成本过高。

**结论**：选 3。`vite.config.ts` 启用 `viteSingleFile()`，构建产物只有 `dist/index.html`。

**代价**
- 产物较大：当前 **1,353,480 字节（约 1.29 MB）**；
- 无法做代码分割/懒加载，首屏即加载全部代码；
- sourcemap 默认关闭，线上排障要靠复现。

## ADR-02 单元格 = 座位（seat-first）

**背景**
会场排座的原子是「某人坐第几排第几座」。旧模型是「画布元素 + 元素内座位槽」，排号需要从元素坐标反推。

**选项**
1. 单元格 = 座位：一格一人/两人，行=排、列=座；
2. 单元格 = 桌子元素：一格一桌，桌内再放座位槽；
3. 保留自由画布，表格只做辅助视图。

**结论**：选 1，不混用两套排号源。

**代价**
- 双人桌要靠「相邻格 + 同 `tableId`」视觉拼接，而不是天然的一桌两槽；
- 导入旧自由布局无意义，直接放弃 v1 数据（见 ADR-09）；
- 用户必须理解「一格就是座位」，学习成本比拖桌子高一点。

## ADR-03 合并区语义由锚点格类型决定

**背景**
最初方案写的是「座位格禁止合并」，评审时被推翻：主席台需要大块背景板、讲台、区域标题，也需要把整块合并后设为特殊元素。

**选项**
1. 禁止座位格合并；
2. 合并后统一视为「座位」；
3. 合并区的语义由锚点格 `kind` 决定，内部格不存内容。

**结论**：选 3。`merges` 只管范围；锚点是 `seat/podium` 就坐人，是 `block` 就不坐人。

**代价**
- 合并/拆分时需要维护锚点内容（`addMerge` 会清空内部格）；
- 合并区跨行列增删时要裁剪（当前是近似处理，见 `known-issues.md`）；
- 用户可能把整块设成座位后仍期待「一个大桌子」，需要文案解释。

## ADR-04 表格用 DOM 绝对定位渲染，不用 Canvas

**背景**
需要单元格内可编辑文本、选区、右键菜单、双击编辑、冻结，以及大量小元素。

**选项**
1. Canvas 自绘一切；
2. DOM + 绝对定位（每格一个组件）；
3. 现成表格组件库（AG Grid / Handsontable）；
4. 虚拟滚动 + Canvas。

**结论**：选 2；Canvas 只用于导出 PNG（`engine/render.ts`）。

**代价**
- 大表性能受限：单元格全部是 DOM 节点，无虚拟滚动。实测 30,000 个座位时拖动列宽 10 步耗 5,791 ms（详见 `known-issues.md`）；常规规模（数百格）实测 10 步仅 5 ms；
- 需要自己实现选区、冻结、键盘导航等 Excel 交互；
- 换来的是：文本可编辑、无障碍焦点、零依赖、样式可控。

## ADR-05 ECharts 按需引入

**背景**
名册/项目页需要饼图、柱图；全量引入 ECharts 会明显增加产物体积。

**选项**
1. 全量 `import * as echarts from 'echarts'`；
2. 按需 `echarts/core` + 仅注册 `PieChart/BarChart` 与必要组件；
3. 用 CSS/SVG 手写图表。

**结论**：选 2，集中在 `src/ui/charts.ts`，由 `UiChart.vue` 统一封装。

**代价**
- 新增图表类型时要手动注册，容易漏；
- 组件封装屏蔽了部分 ECharts 能力（自定义 series 需要改封装）；
- 换来更小的离线包与一致的初始化/销毁逻辑。

## ADR-06 持久化：IndexedDB 优先，localStorage 兜底，内存最后

**背景**
用户核心场景是 `file://` 双击打开。旧实现只要 IndexedDB 打开失败就退化为内存，导致「关掉页面数据就没了」。

**选项**
1. 只依赖 IndexedDB；
2. 只依赖 localStorage；
3. IndexedDB → localStorage → 内存 三级降级；
4. 每次变更自动下载 JSON 备份。

**结论**：选 3。`openStorage()` 探测一次并缓存结果；`loadTables/put*/delete*` 按模式分派；侧栏显示实际后端。

**代价**
- localStorage 是整库单键 JSON（`seat-planning:v2`），每次写都全量序列化；示例数据约 16 KB，接近 5 MB 配额时会失败并退化为内存（当前无超限提示）；
- 两个后端的数据不自动同步：在 A 浏览器用 IndexedDB 存的数据，换到禁用 IDB 的环境看不到，需要「全量备份/导入」；
- 自动下载备份没有采用：浏览器禁止无手势静默下载，且会造成大量文件。

**实测**（Edge 157，`file://`）：IndexedDB 模式刷新/重启进程后数据仍在；强制禁用 IndexedDB 后 localStorage 模式同样跨刷新/跨进程保留，HTML 复制到另一目录仍共享（同 profile）。

## ADR-07 稀疏单元格 + 稳定 seatId

**背景**
1 万格如果全量写 JSON 会很大；插删行列后座位 id 若跟着变，历史分配会错位。

**选项**
1. 二维数组全量存储；
2. 稀疏 `cells: { "r:c": cell }`；
3. 稀疏 + 坐标派生 id。

**结论**：选 2；`seatId` 在格创建时生成（`uid('seat')`），插删行列不重算。

**代价**
- 读取要处理缺失键（`cellAt()` 返回 `undefined`）；
- 复制/粘贴必须重新生成 `seatIds`（`cloneCell(..., regenerate=true)`），否则两个格共用 id；
- 座位 id 与坐标解耦，调试时不能从 id 反推位置。

## ADR-08 排号 = 行，座号 = 行内顺序，视角只改取座顺序

**背景**
旧模型从坐标反推排号，容易因元素错位产生歧义；主席台视角又需要左右换算。

**选项**
1. 排号/座号都持久化到单元格；
2. 排号/座号实时由行列计算；
3. 排号由行计算、座号由行内顺序计算，视角只影响排座取座顺序。

**结论**：选 3。`SeatRef.seatNo` 由 `seatsInRow()` 实时算出；`viewpoint` 只在 `arrange()` 里影响 `hallOrder`。

**代价**
- 座号无法人工指定（不支持「跳号」「自定义座号」）；
- 过道/禁用位不占号，与部分场馆的真实座号规则可能不同；
- 换来表格、座位图、导出三处编号永远一致。

## ADR-09 全新迁移，不兼容 v1 自由画布

**背景**
v1 数据是「元素 + 元素内座位槽」，与表格模型没有一一映射；迁移会有损且长期维护双模型。

**选项**
1. 写 v1→v2 迁移器；
2. 保留双模型运行；
3. 直接删除 v1 代码，新库 `seat-planning-v2`。

**结论**：选 3（用户明确要求）。旧代码 `ElementCanvas`、`layout/*`、`engine/grid.ts`、`engine/geometry.ts` 等已删除；不读取旧库 `seat-planning`。

**代价**
- 老用户的历史布局与排座结果不可用；
- 没有回退路径（只能靠旧版单 HTML 文件本身）；
- 换来数据模型单一、代码量显著下降。

## ADR-10 撤销用整表快照，不用命令模式

**背景**
表格操作种类多（合并、插删行列、填充、改宽高、批量设类型），命令模式要为每种操作写正向/反向逻辑。

**选项**
1. 命令模式（undo/redo 每条命令）；
2. 整表快照（每次提交存一份序列化状态）；
3. 只支持部分操作撤销。

**结论**：选 2，`useLayoutHistory.ts` 最多 80 份，快照为 `{ sheet, zones, canvas }` 的深拷贝。

**代价**
- 内存随表规模增长（30,000 格 × 80 份快照会很大）；
- 快照粒度是「一次 commit」，拖拽过程中不产生中间撤销点；
- 换来所有操作类型统一支持，新增操作只要 `historyPush` 即可。

## ADR-11 工作表上限 300×100，冻结最多 5 行/5 列

**背景**
无虚拟滚动，必须给 DOM 规模设上限；冻结行/列过多会让冻结覆盖层占满视口。

**结论**：`createSheet()` 与「表格设置」都 clamp 到 `300 × 100`，冻结 `0..5`。

**代价**
- 超大会场无法在一个工作表里表达（可拆多个布局）；
- 极限规模下交互卡顿（见 ADR-04 与 `known-issues.md`）；
- 换来可预期的性能边界与简单的实现。

## ADR-12 Excel 导出只出明细，不出图形

**背景**
用户需要把排座结果给不装本工具的同事看。

**选项**
1. 用 SheetJS 生成带样式的可视化座位表（合并单元格、填色、边框）；
2. 只导出「排号/座号/姓名/职级/单位/状态/锁定/区域」明细；
3. 只提供 PNG。

**结论**：选 2；可视化由 PNG 承担（`renderSeatChart`，3× 缩放）。

**代价**
- Excel 里看不到座位布局，需要与 PNG 配合使用；
- 明细是「一座位一行」，105 座就是 105 行（含空位），不是紧凑名单；
- 换来实现简单、字段稳定、方便二次筛选/透视。

## ADR-13 自研表格编辑器，不引入第三方表格库

**背景**
需要离线单文件、零外链，且交互只需覆盖「排座布局」这一垂直场景。

**选项**
1. AG Grid / Handsontable；
2. 自研 `SheetGrid`；
3. 使用 Excel 组件（如 Luckysheet）。

**结论**：选 2。

**代价**
- 选区、冻结、复制粘贴、键盘导航都要自己维护，边界 bug 需要自己修；
- 不具备公式、筛选、条件格式等通用能力；
- 换来包体可控（当前总产物约 1.29 MB）、无 License 约束、样式与业务语义（座位/主席台/特殊块）深度贴合。

## ADR-14 布局编辑页用 CSS transform 缩放，坐标统一除以 scale

**背景**
表格是 DOM 绝对定位，直接改行列尺寸会破坏真实尺寸；缩放必须只影响显示。

**结论**：滚动内容外包一层 `.sg-space`（尺寸 = 逻辑尺寸 × scale），内层 `.sg-inner` 用 `transform: scale()`，`transform-origin: 0 0`。冻结行列、选区、编辑框都在缩放层内；鼠标坐标先判断冻结区，再 `(像素 + scroll) / scale` 还原为逻辑坐标；列宽/行高拖动增量同样除以 scale。

**代价**
- 表头文字不随缩放变小（只缩放位置与宽度），极端缩小下表头会显大；
- 缩放状态不持久化，换布局后回到 100%；
- 换来零重排、缩放不丢选区与排座结果。

## ADR-15 预设 = 布局快照，表存 IndexedDB 独立 `presets`

**背景**
预设要能跨布局复用，同时不能影响已排座项目的座位 id。

**结论**
- `LayoutPreset` 保存一份完整 `LayoutPackage` 快照；
- 从预设新建时复制快照、换新布局 id，并重新生成全部 `seatId`，避免与来源布局串座；
- 2 套内置模板不写库，每次从代码生成，删除按钮对内置模板隐藏；
- 整包导出只包含布局；预设随「全量备份」一起迁移。

**代价**
- 预设是快照，源布局后续修改不会同步；
- 预设体积与布局相同，数量多时备份文件变大。

## ADR-16 导入解析零新增依赖，Word 走自研 ZIP + `DecompressionStream`

**背景**
需要读 Excel / Word / CSV，但离线单文件包要尽量小，不能为了 .docx 引入 mammoth/jszip。

**结论**
- Excel 复用既有 SheetJS；
- CSV/TXT 自写引号感知解析器，UTF-8 失败回退 GBK，分隔符在逗号/制表符/分号/中文逗号中取样；
- `.docx` 只读 `word/document.xml`：自写 ZIP 中央目录读取，deflate 用浏览器原生 `DecompressionStream('deflate-raw')`，再用 DOMParser 按段落/表格行抽取；
- `.doc` 旧二进制格式明确拒绝并提示另存；
- 姓名解析覆盖序号、括号备注、空格/短横线后缀、性别、电话、多人并列。

**代价**
- 依赖 Chromium 的 `DecompressionStream`（Tauri WebView2 / 现代 Edge 均可用），老浏览器会给出明确提示；
- 不解析 Word 页眉页脚、文本框、批注；
- 换来零新增依赖、包体不膨胀。

## ADR-17 自动保存 900ms 防抖 + 切换/关闭兜底

**背景**
原先只有手动保存，刷新或切页会丢草稿。

**结论**
- 布局、名册、项目三处都在变更后 900ms 自动落盘；
- 切换实体前先 flush 当前草稿；删除实体前先取消待执行的自动保存，避免「删了又被写回」；
- `beforeunload` 在仍有未保存变更时提示；
- 手动保存会取消待执行的定时器。

**代价**
- 高频编辑时每 900ms 可能写一次整库（localStorage 模式是全量序列化）；
- 自动保存没有可见的成功提示，仅在页脚保留脏标记/保存按钮。

## ADR-18 导出按 12000px 上限自动降倍，默认配色与界面一致

**背景**
大布局 4× 导出会超过 Canvas 尺寸上限，浏览器可能直接产出空白图；同时导出图与界面配色需一致。

**结论**
- 导出倍率可选 2×/3×/4×，打印可选 A4 横向/纵向；
- 按 `12000 / 画幅` 计算可用倍率并自动下调，toast 告知实际倍率；
- Canvas 渲染同步界面配色：普通座位浅墨青、主席台加深、未排座虚线、固定空位斜纹、已排座左侧职级色条、请假暖黄。

**代价**
- 极端大布局可能只能 1× 左右输出；
- 斜纹是自绘 pattern，打印分辨率下纹理较细。

## ADR-19 预设与备份的版本口径

**结论**
- `LayoutPackage.schemaVersion` 仍为 `2.0`；
- 全量备份升级为 `2.1`（新增 `presets` 字段），导入同时接受 `2.0` / `2.1`，更高版本直接拒绝并提示；
- 导入按 id `bulkPut`/`upsert` 合并，不静默清空本地数据；
- 导入结果返回各表写入数量与结构告警。

**代价**
- 同 id 记录会被备份覆盖；
- 没有「导入前自动备份」步骤，误覆盖只能靠事先手动导出。

## ADR-20 会场编号、座位详情浮层与「请假」口径

**背景**
用户要求：布局页顶部列标改数字；每排座位号按排座算法顺序（中间为 1、左右交替向外），而不是从左到右顺排；点座位从上方/下方弹卡片；请假人员不参与排座，但在右侧单独列出，名册里可切换「在位/请假」。

**结论**
- 列标统一为数字（`1..N`），布局页选区标识改为「N 列 M 行」，不再使用 `A1:B2` 形式；`colLabel()` 已删除。
- 新增 `seatOrderMap(layout, rules)`：主席台排用 `podiumOrder`，台下用 `hallOrder`，按算法落座顺序给每排座位编号；座位物理位置不变，只改显示编号。座位图、详情卡片、Excel 导出共用同一份编号。
- 座位详情改为 `Teleport` 到 body 的浮层卡片：锚定被点座位，优先向下，空间不足翻到上方；滚动、滚轮缩放、窗口尺寸变化时用 `requestAnimationFrame` 重新定位；点击外部、再点同一座位或 Esc 关闭；打开时焦点进入卡片，Esc 关闭后焦点回到座位。
- 请假改为人员级状态 `Member.status: 'present' | 'leave'`，不再写入 `Assignment.status`。排座时直接排除请假者，统计里请假只计数、不占座；右侧新增「请假」tab，名册页提供「在位/请假」切换。
- 备份 schema 升为 `2.2`，导入兼容 `2.0/2.1/2.2`；旧数据 `active:false` 迁移为 `leave`，旧备份里请假者的座位安排在载入/导入时清理。
- 移除 `RuleSet.podiumLeave`（留空位/前移）——请假者根本不入座后该规则没有意义，规则面板改为静态说明。

**代价**
- 主席台偶数座位时「1 号」是中间两人里靠左的一位；遵守「以左为尊」时 2 号会出现在观众视角的右侧，和台下「中间偏左为 1、偏右为 2」的观感不完全一致，这是两套既有规则的直接结果。
- 关闭页面再打开时浮层不会恢复（座位选中状态不持久化）。
- 旧版项目中状态为「停用」的人员会被理解为请假，而不是从名册中删除。

## ADR-21 工作台分区、状态归属与座位配色

**背景**
用户指出：布局页左侧布局列表应改成顶部一行 tab；布局页与排座项目页的生硬竖线应改为淡背景分区；交换座位时两个座位都要高亮；「在位/请假」应设在排座项目里而不是名册页；整体设计需要一次完整审核（信息层级、留白、控件形态、座位状态可读性、操作动线）。

**结论**
- 布局页删除左侧 `lv-rail`，布局列表改为顶部一行 tab（激活项白底细边，其余透明），新建按钮紧随其后；「存为预设 / 从预设新建 / 导出全部 / 删除」收进同一行右侧。布局名称不再在工具栏重复。
- 新增令牌 `--bg-sunken: #f5f7f7`，用于右侧详情面板、布局 tab 条等「分区底色」；排座项目右侧面板取消 `border-left` 与卡片描边，改为淡底色 + 圆角，和座位图之间靠色差分层。
- 交换座位时：拖拽源座加 `is-drag-source`（虚化）、目标座加 `is-drag-over`（虚线框）；落座交换后两个座位同时加 `is-flash` 高亮 950ms。`prefers-reduced-motion` 下改为静态描边。
- 「在位/请假」只在「排座项目 → 名单」每行切换；请假 tab 提供「恢复在位」。名册页的状态列改为只读标签，表单不再编辑状态。切换为请假会立即从当前项目分配中移除并保存名册/项目，避免刷新后残留。
- 座位配色加强区分：已排座 `#e7f1f0` + 描边 `#b6d1cf`，空位白底虚线，主席台 `#d9e9e7`，固定空位斜纹，锁定/请假用暖色；图例色块同步。
- 布局编辑器去掉逐格重复文字：同名桌带每排只显示一次桌名，删除每格重复的「双人位」（两个圆点已表达座位数），降低网格噪声。

**代价**
- 请假只能在打开某个排座项目时操作；只改名册不建项目时无法标记请假。
- 顶部 tab 在布局很多时会横向滚动，没有下拉总览；左侧原有的常驻列表不再可见。
- 两个座位的高亮依赖动画结束自动清除，快速连续换座以最后一次为准。

## ADR-22 布局由「列表」承担，预设概念下线；编号取消镜像；区域可反向查看

**背景**
用户连续提出：布局顶部改成「当前布局 + 切换/新建 + 管理菜单」；预设这套概念不再需要；排座编号以就座者自身左右为准；区域要能反向定位和高亮；主席台/普通位容量不能只限 1–2 人；左侧不应再有描边线。

**结论**
- **布局切换**：顶部左侧只显示「当前布局：名称」，右侧是「切换」「新建」两个按钮 + 「管理布局」齿轮菜单；菜单含重命名、复制为新布局、删除（二次确认）。「存为预设 / 从预设新建 / 存为预设」入口全部移除，`LayoutPreset`、`presets` 表与备份中的 `presets` 字段不再使用（旧备份仍可读取并忽略该字段）。ADR-15 作废。
- **编号方向**：删除 `RuleSet.viewpoint` 与所有镜像逻辑。主席台与台下统一使用 `centerOutOrder()`：1 号居中，2 号紧邻其右侧，3 号紧邻其左侧，4 号在 2 号外侧……双人桌偶数座时也保证 3 号回到 1 号**另一侧**（此前会把 3 号排到 2 号外侧，导致与 1 号同侧）。ADR-08 的「视角只影响取座顺序」改为「不设视角，编号只由座位左右关系决定」。
- **容量**：`SheetCell.seats` 由 `1 | 2` 放宽为 `number`（1–50，`clampSeats()` 归一化），助手栏与属性面板都提供「单人位 / 双人位 / 自定义 N 人」；`seatsInRow()`、导出 PNG、座位图、Excel 明细全部按 N 个座位槽展开，合并块与主席台同样适用。
- **区域反向查看**：属性面板的区域列表改成可点击的行，显示每个区域的格子数；点击后画布以「淡色填充 + 主色虚线」高亮该区域全部格子，再点取消。区域的分配/解除仍走 `historyPush` 快照，Ctrl+Z 可恢复到分配前状态，并新增「清除选区归属」。
- **区域人员分配**：新增 `RuleSet.zoneRules`，支持按级别快捷指派（多级别并集）、排除级别、手动勾选人员；引擎里手动人员最先落位，其次区域级别规则，最后才轮到职级分层；冲突写入 `warnings`。UI 在规则面板内提供影响人数预览与「撤销上次区域修改」。
- **视觉**：全局左侧栏去掉 `border-right`，改用 `--bg-subtle` 淡底色；名册姓名后补「级别 · 单位」。

**代价**
- 旧项目缺少 `zoneRules`，载入时补空数组；旧数据里的 `viewpoint` 字段被忽略，不会做迁移；
- 预设下线后，跨布局复用只能靠「复制为新布局」；
- 自定义容量上限 50，超大主席台（如百人长条）需要拆成多格；
- 区域规则与职级分层同时存在时只提示、不阻止，最终以区域规则为准。

## ADR-23 排座项目冻结名册快照；职务只展示不排序；名册顺序手动决定

**背景**
用户指出：人员名册会周期性变化（换单位、职级升降、调入调出），排座项目一旦排好就不应被名册变动自动改写，否则每次改名册都会把已排好的会场打乱。同时需要「职务」信息用于展示与筛选，但不能因为职务变动影响排序；名册顺序也必须由用户手动决定，系统不做自动排序。

**结论**
- **快照解耦**：项目创建时把当前 `RosterPlan` 深拷贝到 `Project.rosterSnapshot`。`rosterOf(project)` 优先返回快照，排座引擎、座位图、名单、导出全部读快照。名册后续增删改、排序调整都不会自动作用到项目；旧项目载入时补快照，已有座位分配保留。
- **手动更新差异清单**：项目「名单」提供「手动更新」入口，将当前名册与快照比对，按「单位变更 / 职级调整 / 职务变更 / 已不在名册 / 新增人员 / 顺序调整」分组；默认全选，可逐项勾选后应用。应用才写入快照，并提示「名册快照已更新，建议重新排座」；未应用时项目顶部显示「名册已变化，N 项待更新」。
- **顺序差异聚合**：排序变化不逐人罗列，只生成一条「顺序调整」聚合项；应用时只按双方共有成员重排快照，快照独有成员保持末尾，避免把已移除人员重新排进来。
- **职务字段**：`Member.duty` 支持新增/编辑、批量添加与 Excel/CSV 导入（表头匹配「职务 / 职位 / 岗位」），可在名册与项目名单中搜索、筛选。职务**不参与排序**，不引入职务序列、不做前后加权。
- **手动排序**：名册表格整行可拖拽（顶部手柄列），按行中点判定插入到前/后并显示落位线；落位立即改 `members` 数组顺序并提示保存。筛选状态下禁用拖拽，避免可见顺序与完整数组索引错位。顺序持久化，排座时作为同职级同单位内的先后依据。
- **展示分层**：座位格内空间有限，仍只显示「姓名 + 职级·单位」；职务在排座项目名单行（标签）与座位详情卡（独立一行）完整展示。

**代价**
- 项目与名册彻底解耦后，名册更新不会自动同步；用户必须主动打开差异清单确认，忽略的差异会持续提示。
- 顺序变化只能整体应用或整体忽略，不支持只应用部分人的相对顺序。
- 拖拽排序依赖完整列表，筛选态不可拖动，需要先清除筛选。
- 职务为自由文本，不做字典校验；同名职务的不同写法（如「主任」「主任委员」）会分别出现在筛选项里。

## ADR-24 座位槽等分所在格；只读排座图不画区域名；职级用淡底而非色条

**背景**
排座图的座位槽原先在格内预留 4–8px 缝隙，形成「小卡片」观感；合并主席台仍渲染「主席台」区域名，压住第一名人员；每个已排座格左侧画 2px 职级色条，且格内同时显示单位，导致双人位出现「副科级 · …」截断。

**结论**
- `seatsInRow` 的槽位严格按 `rect.w / n` 等分，`y/h` 占满整格，不再留缝。合并主席台 N 个座位即 N 等分，导出与界面共用同一几何。
- 只读模式（排座图）不渲染桌名/区域名，座位内容独占整格；编辑/布局页仍保留名称与座位圆点。
- 已排座格去掉左侧色条，改用职级色 9% 的极淡底色区分；空位透明，保留固定空位/过道的斜纹底。
- 格内只显示「姓名 + 职级」，姓名与职级允许换行；单位、职务仅在名单与座位详情卡展示。

**代价**
- 合并块内没有分隔线，N 等分只能靠底色差异与姓名等距排布感知；同职级相邻时边界更弱。
- 只读图不显示区域名，识别主席台位置依赖布局上下文与座位编号。
- 极窄双人位中长姓名仍可能换成两行，但不会再出现「职级 · …」残句。

## ADR-25 边框整表去重 + 设备像素对齐；座位序号开关随项目保存

**背景**
默认边框对每个座位/主席台矩形独立描边，相邻格共享边被重复绘制；显式边框再叠一层。`non-scaling-stroke` 让线宽不随缩放变化，但重叠描边在亚像素位置会加深或发虚。更隐蔽的是座位按钮的淡色底画在边框之上，按亚像素随机盖掉一部分线，导致同图线条粗细不一。

**结论**
- 边框只在引擎层收集一次：`collectBorderLines` 按「同一直线上的区间」切分，每段只保留一条（显式优先、其次默认），界面与导出共用。
- 线宽与坐标都在绘制前换算到设备像素：奇数线宽对齐 `k+0.5`、偶数对齐 `k`，`stroke-width = width / scale`，不依赖 `non-scaling-stroke`；外圈允许溢出 0.5px，避免被 SVG 视口裁细。
- 边框 SVG 置于座位叠加层之上（`z-index: 4`），不再被座位底色覆盖。
- 序号是项目级显示偏好：`Project.showSeatNumbers`，缺省 true；画布与导出读取同一值，导出序号取与画布相同的座位顺序。

**代价**
- 边框几何每帧随缩放重算并逐条输出 `<line>`，节点数约为边数的 1–2 倍（千级座位仍在毫秒级）；换来的是可预测的 1px 观感。
- 边框压在姓名上层，极窄格里线可能擦到文字边缘（线本身在格边界，不遮挡正文）。
- 序号开关只影响显示，不改变座位顺序数据。

## ADR-26 布局操作栏只留高频动作；容量归属性面板；默认黑框可显式覆盖；辅助网格只在编辑态

**背景**
布局页操作栏原先把「座位规格（单人/双人）」和「边框」都做成常驻按钮组，挤占横向空间；边框样式入口以文字形式出现，与行列/合并/类型平铺；编辑态缺少整表参考线，空表时难以判断行列边界。

**结论**
- 操作栏删除「座位规格」整组：座位容量改由右侧属性面板统一负责，单格/多选都作用于当前选区。
- 边框收为单个图标按钮 + 下拉：快捷边框、线型、粗细、线色都在下拉内完成，不再占用常驻宽度。
- 座位/主席台默认绘制黑色 1px 实线；用户显式设置某几边时，该格不再叠默认框，只画选中的边；「清除边框」写入空数组，表示该格显式无框。
- 编辑态恢复整表淡虚线辅助网格（合并块内部不画），只读排座图与导出图不绘制；导出仍只输出 `collectBorderLines` 的真实边框。
- 主席台文字改成与普通座位同一量级（12px、主文字色），不再按块尺寸放大。

**代价**
- 容量入口从「选中即可见」变成「右侧面板可见」，窄屏下需要滚动属性面板。
- 显式边框是整格覆盖语义：只设左边框会去掉该格其余默认边，需要用户主动补全。
- 辅助网格在密集表上会增加视觉噪声，但密度受缩放影响，且不进入导出。

## ADR-27 本地数据管理收口到「设置中心」；座位姓名两端对齐；名单导出按在位口径

**背景**
左下角原本是三行存储说明文案，用户无法在应用内查看数据量或清理数据；全量备份/导入散落在「排座项目 → 导出与备份」里，与导出 PNG/Excel 混在一起。座位格内姓名只用居中/左对齐，两字名与三字名两侧留白不一致。排座结果的 Excel 明细包含空位与请假，不适合直接作为「在位人员名单」上报。

**结论**
- 左下角改为「设置中心」入口，面板内展示各表条数与 JSON 体积、总占用、存储位置；提供导出全量备份、导入备份、清空数据（二次确认）三项操作。
- 「排座项目 → 导出与备份」删除全量备份/导入备份按钮，只保留 PNG / Excel / 在位人员名单 / 打印，避免两套入口。
- 清空数据后以 `loadAll(false)` 重新读取，不自动灌入示例数据；示例数据只在首次空库启动时生成。
- 座位姓名在画布用 `text-align-last: justify` + `text-justify: inter-character`，导出按字符宽度均分剩余空间逐字绘制，做到首尾贴边、字距均匀。
- 新增「在位人员名单」Excel：姓名 / 职级 / 单位 / 职务 / 座位号 / 区域，跳过固定空位、空位与请假人员。

**代价**
- 数据体积用序列化字节数估算，与 IndexedDB 实际磁盘占用存在差异，但足以判断量级。
- 两端对齐会让两字名中间留出较大字距，属于用户明确要求的效果。

**修订（2026-11-10）**：容量入口已从布局属性面板整体移除，改由排座项目设置；见 ADR-28。

## ADR-28 桌容量归排座项目，布局页只定义位置

**背景**
会场布局描述的是「固定会场形状与桌椅位置」；一张桌坐几人属于每次会议的实际安排。ADR-26 把容量放进布局属性面板，导致同一份会场要按不同会议反复改布局，且共享布局会被排座项目污染。

**选项**
1. 容量留在布局属性面板；
2. 容量写回布局的 `seats` 字段并让项目只读；
3. 布局保留旧 `seats` 作为兜底，项目用 `seatCapacity` 覆盖并派生 Sheet。

**结论**
- 选 3。`Project.seatCapacity`（`"行:列" → 人数`）由排座项目维护，`applySeatCapacity` 返回派生 Sheet，不改共享布局；旧布局的 `seats` 继续可读。
- 布局页删除所有容量入口（属性面板、操作栏、右键菜单、填充对话框），只保留桌位/合并/区域/尺寸/样式；属性面板与填充对话框各留一句「一桌坐几人请在排座项目中设置」。
- 单格、选区批量、自定义 N 人都在排座项目内完成；缩容时被移出的人员会集中提示。

**代价**
- 旧布局的 `seats` 与项目覆盖可能不一致，需要 `applySeatCapacity` 做兼容；
- 布局页不再能直接看到「这张桌能坐几人」，只能通过座位点数量间接判断。

## ADR-29 画布平移直接用滚动值，不用变换矩阵

**背景**
两个画布都支持缩放，中键拖动需要任意比例下都对位。若通过 CSS transform 平移，需要把屏幕位移换算回画布坐标，缩放变化后容易累积误差。

**结论**
- 中键 `pointerdown` 记录起点与 `scrollLeft/Top`；window `pointermove` 直接按指针位移增量改滚动值。滚动单位就是视口像素，缩放只影响内容尺寸，天然对位。
- `pointerdown` 上 `preventDefault()` + `auxclick/mousedown` 阻止中键自动滚动；`.is-panning` 统一 `grabbing` 光标并禁用选择；`pointerup` / `pointercancel` 解绑。

**代价**
- 平移依赖滚动容器，若未来改成无限画布需重写；
- 中键事件在部分触控板驱动下可能缺失，保留空白区域拖拽等其他方式。

## ADR-30 设置中心改为独立页面，按数据库视角呈现

**背景**
ADR-27 把设置中心做成左下角弹层，信息密度低，也无法容纳逐表统计与风险说明。

**结论**
- 左侧导航新增「系统 / 设置中心」，与「名册与组织 / 会场布局 / 排座项目」同级；原底部弹层入口删除。
- 页面按表列出记录数、占用与占比，顶部给总占用、存储位置与持久化状态；备份/导入/清空放在右侧操作列。
- 清空使用模态二次确认，逐项列出会被删除的数据量，明确「无法撤销，只能通过备份恢复」，并提供「先导出备份」。

**代价**
- 设置从「随时点开」变成「切换页面」，但信息量与风险提示更完整；
- 数据体积仍按 JSON 序列化估算，与 IndexedDB 实际磁盘占用存在差异。

## ADR-31 座位信息行改为用户自选开关；姓名恢复居中

**背景**
ADR-27 的姓名两端对齐在低缩放下会把三字名拉成散开的单字，观感更差；座位下方原本固定显示职级，职务与单位无处展示。

**结论**
- 姓名恢复 `text-align:center`，画布与导出共用同一绘制逻辑。
- 新增 `showRank/showDuty/showUnit` 三个独立开关（与 `showSeatNumbers` 并列），默认只显示职级；状态随项目保存，导出读取同一组开关。
- 信息行纵向排列、单行省略，整段裁剪到座位矩形；三行全开也不溢出格子。

**代价**
- 三行信息在低缩放或小格子里会以省略号收尾，需要放大查看；
- 旧项目没有新字段，加载时按默认值补齐。

## ADR-32 规则面板用「职级多选弹窗」替代两套胶囊

**背景**
「职级分层」与「区域人员分配」各自渲染一整排职级胶囊，同屏出现两套级别选择，层级难辨、重复堆叠，侧栏下拉还被截断。

**结论**
- 基础三项使用短标签，完整含义放进下拉项 `hint`；两类规则用「1 / 2」序号分组。
- 职级选择改为两处共用的多选弹窗：按钮只显示已选范围与 `N/总数`，点开勾选；区域排除级别继续折叠在 `details` 里。
- 区域规则的撤销移到规则头部，底部说明默认折叠，整个面板在默认侧栏高度内不滚动。

**代价**
- 查看全部可选职级需要多一次点击；
- 已选职级很多时按钮内以省略号截断，靠 `N/总数` 判断范围。

## ADR-33 容量操作以「点选时的桌」为准，预设与数字框互相同步

**背景**
座位槽数量变化后旧 `seatId` 可能失效，详情卡若只依赖 `seatIndex.get(seatId)`，标题会退化为「座位」、`selectedCellKey` 为空，点「应用」静默无效；同时预设高亮只看当前容量，输入自定义值时仍误亮「单人 / 双人」。

**结论**
- 点选座位时把 `row/col` 一并存下并随 `pick` 事件传出；`selectedCellKey`、标题、容量读取都以「当前 id → 点选时的桌」两级回落。
- 容量变化后若选中 id 失效，自动改选该桌第一个座位，卡片不脱锚。
- 预设按钮高亮由数字框 `capCustom` 驱动（输入即同步、自定义值取消预设），应用统一做 `clampSeats` 收敛并给出 toast。
- 缩容只移除确实消失的座位槽上的分配，提示被移出人员姓名；`flash` 复用单一定时器，避免旧定时器擦掉新提示。

**代价**
- 详情卡多依赖一份点选行列状态；切换项目/关闭卡片时需一并清理。

## ADR-34 取色预览不进历史，提交时只记一步

**背景**
样式面板使用原生取色器，拖动过程连续派发 `input`；若沿用原有「每次改动即 `historyPush`」，一次调色会生成大量撤销步，且预览阶段就会污染历史。

**结论**
- `input` → `preview-style`：只改模型并 `markDirty()`，不写历史；`change` → `style`：调用一次 `commit()`。
- 快照历史天然满足「一次调色一步撤销」：预览期间 `hIndex` 停在调色前，提交后追加最终快照；无实际变化时 `historyPush` 因快照相同自动去重。
- 预览对当前选区（含多选）逐格套用，底色与文字色分别对应各自属性。

**代价**
- 拖动超过自动保存间隔时中间态可能被落盘，但撤销仍以提交后的单步快照为准。

## ADR-35 批量容量用「空白起手框选」，选框画在视口层

**背景**
批量容量原先只能逐桌点选。画布本身已有单击看详情、拖拽换位两种指针交互，加框选必须避免手势冲突，且画布支持缩放与滚动，选框坐标不能只在按下时算一次。

**结论**
- 框选只在批量容量模式生效；指针按下用捕获阶段监听在面板根节点，命中座位、行列头、底栏缩放控件、原生滚动条一律放行给原有交互。位移不足 4px 视为单击空白（清空选区）。
- 选框用视口坐标绘制在面板根节点（`position:absolute` + `pointer-events:none`），不进入缩放层，避免被 `transform: scale()` 二次缩放。
- 每次 `pointermove` 用缩放层的实时包围盒把「按下点」重新换算成工作表坐标，因此拖动中滚轮滚动、或滚动后重新框选都不会错位；选择判定按每格座位包围盒并集与矩形求交。
- Ctrl/Meta 由 `pointerup` 上的修饰键决定追加或替换；Esc 与空白单击清空。
- 容量应用沿用 `setCapacity`，缩容提示、撤销与持久化逻辑完全复用。

**代价**
- 空白起手意味着座位铺满的区域无法直接起手，需从桌间空隙/画布留白开始；
- 拖动中不自动滚动，需要用户自行滚轮移动画布。

## ADR-36 历史快照可批量清理，但永不参与运行时引用

**背景**
排座前自动留存的快照越积越多，用户希望能在项目内多选删除、在设置中心一键清空，同时担心误删影响正在使用的数据。

**结论**
- 快照只是「排座前版本」的独立记录，项目、名册、布局、预设都不持有快照 id，恢复操作是把快照内容拷回项目，因此不存在「正在被使用」的快照，可以任意删除。
- 既然没有保护对象，就不做「禁止删除基准快照」的硬限制，而是把删除后果写进确认文案：删除后无法恢复到这些旧版本，当前排座结果与实体数据不受影响。
- 项目内删除走通用确认弹窗（可撤销前二次确认）；设置中心一键清空走独立弹窗，必须列出条数、可释放空间、影响范围与不可撤销，避免误触。
- 清理只调 `deleteSnapshots` / `clearSnapshots` 两张表的删除，不触发 `loadAll` 之外的实体数据写入；设置中心清空后重新统计，保证记录数与占用即时刷新。

**代价**
- 快照列表改为全量展示（可滚动），条目极多时需要滚动查找；
- 清空是全局操作，会一并清掉所有项目的历史快照。

## ADR-37 下拉弹层统一走 useAnchoredPopup，选项单行且不内部滚动

**背景**
触发器分散在侧栏、工具栏和缩放容器内，历史上各自算坐标：有的相对最近定位祖先生成，有的把弹层挂到带 transform 的容器里，缩放后坐标被二次变换，出现向下偏、左边缘不齐、压住统计条。选项又把名称和「30 人」拆成两行，列表过高。

**结论**
- 弹层一律 Teleport 到 body，定位用 position: fixed + `getBoundingClientRect()`，与触发器同处视口坐标系，不受祖先 transform/overflow 影响。
- 统一 gap 4px、左对齐、宽度取 `max(触发器宽, minWidth)`；下方空间不足且上方更宽时向上翻转；打开期间监听 scroll(capture)/resize/visualViewport/ResizeObserver 实时重算，而不是关闭弹层。
- 选项只保留必要文字，名称单行 32px 高，文字溢出省略；不提供 `hint` 副信息。正常条目数靠精简文案与紧凑行高一次展示完，不出现滚动条。
- 高度兜底：弹层上限按视口可用空间动态计算（上下各留 12px，最多取可用空间的 90%）；上下都放不下时选空间较大的一侧，弹层不超出视口。只有内容超过兜底上限的极端情况才出现内部滚动（`overflow-y:auto` 仅在封顶时写入）。窗口 resize / 缩放 / 触发器尺寸变化后重新计算上限。

**代价**
- 极端条目数会触发内部滚动（仅在内容超过视口兜底上限时），与「正常条目数不滚动」的目标不冲突。

## ADR-38 元素与单元格解耦：几何独立存储，锚定模式只决定换算方式

**背景**
讲台、人形、门等需要任意摆放，但用户又希望部分元素随行列增删移动。若把元素做成单元格类型，就回到「元素跨格 = 合并」与「单元格 = 座位」冲突的老问题。

**结论**
- 元素始终保存自己的宽高、旋转和锚点描述；`anchor.mode='cell'` 时用覆盖行列 + 比例偏移换算，`free` 时直接用绝对坐标。渲染层只认 `resolveGeometry` 的结果。
- 属性面板切换锚定方式时做双向换算（`anchorToCell` / `anchorToFree`），保证切换瞬间视觉位置不变。
- 拖动/缩放元素时先固化为 `free` 以获得连续反馈，松手后再按当前几何反推覆盖行列重新锚定，避免交互过程中被行列吸附拉扯。
- 行列增删只平移 `cell` 锚点（`shiftElementAnchors`），`free` 元素保持绝对位置。

**后续（2026-11-10）**

- 面板不再暴露锚定切换：新元素一律浮于单元格。`cell` 模式保留为**旧数据读取通道**（`normalizeElements` / `resolveGeometry` 仍能还原原位置），`anchorToCell` 仅内部保留，不再有 UI 入口。

**代价**
- 固定单元格元素在行列被整体删除时可能失去绑定行列，需要 `normalizeElements` 夹取到有效范围。

## ADR-39 元素图形由一份 SVG path 驱动画布、预览与导出

**背景**
元素库预览、画布渲染、Canvas 导出如果各画各的，图形会漂移，导出与屏幕不一致。

**结论**
- 每个元素在 `ELEMENT_SHAPES` 中定义 100×100 坐标系下的填充路径与细节线；元素库预览、`SheetElementLayer`、`engine/render.ts`（Path2D）共用。
- 选中框、旋转柄、缩放手柄只在可编辑画布出现；只读排座图关闭 pointer-events，避免遮挡座位点击。
- 讲台默认 `bordered: false`，符合「讲台是一个无边框形状」的要求；其它元素按用途给默认描边。
- 文字样式（字号、颜色、字体族）落在元素数据上，画布与导出读同一份字段。

**代价**
- 新增元素必须同时提供 path 与默认元数据，否则预览与画布会退化；已在 `ElementKind` 上做类型约束。

## ADR-40 属性面板共用一套演算规格，文字位置进入元素数据

**背景**

元素面板、选区面板、排座规则面板由不同轮次拼出来：分区标题分别是 10.5px / 11px / 12px，控件高度 26–28px，圆角 4–5px，选区面板还用原生 checkbox 与原生取色器，点开字体还能看到浏览器原生 select。用户把三个面板摆在一起时能一眼看出不是一套东西。同时元素文字此前只能居中，无法像 PPT 一样调位置。

**结论**

- `style.css` 提供唯一一份 `.insp-*` 规格：面板内边距 12px、分区标题 12px/600/`--text-secondary`、标签列 40px、控件高 28px、圆角 `--radius-xs`（6px）、字号 `--fs-xs`（12px）、开关 34×20、色板 21px（文字色 18px）、快捷按钮 24px、操作按钮 28px、分区之间用 `--border-soft` 分隔。
- 两个属性面板根节点共用 `.insp-panel`；三个面板的分区标题共用 `.insp-title`，规则面板保留编号圆点。
- 所有下拉必须是 `UiSelect`（与「名册方案 / 会场布局」同一组件），禁止原生 `select`；开关、色板、分段控件同样走共用类名。
- 快捷说明不再常驻底部：收进 `<details class="insp-keys">`，默认折叠。
- 文字位置作为元素数据的一部分：`textAlign`（左/中/右）、`textVAlign`（上/中/下）、`textOffsetX/Y`（工作表单位）。画布用 flex 对齐 + `translate`，导出用 `textAlign` / `textBaseline` + 相同内边距与偏移；`elementTextPadding()` 统一两侧留白，人形缺省贴底。

**后续（2026-11-10 复核）**

并排复查又清掉三处残留，以下三条此后为唯一规格：

- **色板只有一种形态**：`.insp-swatch` 与 `.insp-color` 都是 20×20、圆角 5px 的方块，不再有圆形或 18/21px 的变体；文字色、填充色、选区面板两套色板、自定义取色入口全部同形同尺寸。自定义取色不再暴露原生控件外形，用 conic-gradient 底 + 透明 input 覆盖。
- **次要按钮只有一种形态**：`.insp-quick button` 与 `.insp-actions .insp-btn` 均为 28px 高、6px 圆角、`--border-strong` 描边、12px 字号；不再出现纯文字链或行内 24px 小按钮。「清除底色」「清除选区归属」「＋ 新建区域」「偏移归零」都走这一形态。
- **说明只有一种入口**：面板内不常驻小号灰字。需要解释的内容统一收进底部 `<details class="insp-keys">`（12px、行高 1.6、默认折叠），元素面板叫「快捷键」，选区面板叫「提示」。

**代价**

- 三个面板不再各自定义标题与控件样式，调整规格必须改全局 `.insp-*`；这是有意的约束。
- 文字对齐的 CSS 与 Canvas 两套实现需要保持同一套内边距/偏移公式，新增对齐方式时两边都要改（helpers 已集中在 `engine/elements.ts`）。
