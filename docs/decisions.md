# 技术决策记录（ADR）

> 记录本项目已经做出、且会长期影响维护方式的关键决定。
> 每条包含：背景 → 选项 → 结论 → 代价。日期以迭代轮次表示。

---

## ADR-01 交付形态：Vite + `vite-plugin-singlefile` 单 HTML

**背景**
使用场景是双击 HTML 离线排座，不能依赖服务器、内网地址或安装包。

**选项**
1. 纯手写单文件（无构建）—— 没有组件化、类型检查，代码量上千行后不可维护；
2. Vite 构建 + 手动内联资源 —— 多一步脚本，容易漏资源；
3. Vite + `vite-plugin-singlefile`；
4. Electron/桌面壳 —— 体积与分发成本过高。

**结论**：选 3。`vite.config.ts` 启用 `viteSingleFile()`，构建产物只有 `dist/index.html`。

**代价**
- 产物较大：当前 **1,353,480 字节（约 1.29 MB）**；
- 无法做代码分割/懒加载，首屏即加载全部代码；
- sourcemap 默认关闭，线上排障要靠复现。

## ADR-02 单元格 = 座位（seat-first）

**背景**
会场排座的原子是「某人坐第几排第几座」。旧模型是「画布元素 + 元素内座位槽」，排号需要从元素坐标反推。

**选项**
1. 单元格 = 座位：一格一人/两人，行=排、列=座；
2. 单元格 = 桌子元素：一格一桌，桌内再放座位槽；
3. 保留自由画布，表格只做辅助视图。

**结论**：选 1，不混用两套排号源。

**代价**
- 双人桌要靠「相邻格 + 同 `tableId`」视觉拼接，而不是天然的一桌两槽；
- 导入旧自由布局无意义，直接放弃 v1 数据（见 ADR-09）；
- 用户必须理解「一格就是座位」，学习成本比拖桌子高一点。

## ADR-03 合并区语义由锚点格类型决定

**背景**
最初方案写的是「座位格禁止合并」，评审时被推翻：主席台需要大块背景板、讲台、区域标题，也需要把整块合并后设为特殊元素。

**选项**
1. 禁止座位格合并；
2. 合并后统一视为「座位」；
3. 合并区的语义由锚点格 `kind` 决定，内部格不存内容。

**结论**：选 3。`merges` 只管范围；锚点是 `seat/podium` 就坐人，是 `block` 就不坐人。

**代价**
- 合并/拆分时需要维护锚点内容（`addMerge` 会清空内部格）；
- 合并区跨行列增删时要裁剪（当前是近似处理，见 `known-issues.md`）；
- 用户可能把整块设成座位后仍期待「一个大桌子」，需要文案解释。

## ADR-04 表格用 DOM 绝对定位渲染，不用 Canvas

**背景**
需要单元格内可编辑文本、选区、右键菜单、双击编辑、冻结，以及大量小元素。

**选项**
1. Canvas 自绘一切；
2. DOM + 绝对定位（每格一个组件）；
3. 现成表格组件库（AG Grid / Handsontable）；
4. 虚拟滚动 + Canvas。

**结论**：选 2；Canvas 只用于导出 PNG（`engine/render.ts`）。

**代价**
- 大表性能受限：单元格全部是 DOM 节点，无虚拟滚动。实测 30,000 个座位时拖动列宽 10 步耗 5,791 ms（详见 `known-issues.md`）；常规规模（数百格）实测 10 步仅 5 ms；
- 需要自己实现选区、冻结、键盘导航等 Excel 交互；
- 换来的是：文本可编辑、无障碍焦点、零依赖、样式可控。

## ADR-05 ECharts 按需引入

**背景**
名册/项目页需要饼图、柱图；全量引入 ECharts 会明显增加产物体积。

**选项**
1. 全量 `import * as echarts from 'echarts'`；
2. 按需 `echarts/core` + 仅注册 `PieChart/BarChart` 与必要组件；
3. 用 CSS/SVG 手写图表。

**结论**：选 2，集中在 `src/ui/charts.ts`，由 `UiChart.vue` 统一封装。

**代价**
- 新增图表类型时要手动注册，容易漏；
- 组件封装屏蔽了部分 ECharts 能力（自定义 series 需要改封装）；
- 换来更小的离线包与一致的初始化/销毁逻辑。

## ADR-06 持久化：IndexedDB 优先，localStorage 兜底，内存最后

**背景**
用户核心场景是 `file://` 双击打开。旧实现只要 IndexedDB 打开失败就退化为内存，导致「关掉页面数据就没了」。

**选项**
1. 只依赖 IndexedDB；
2. 只依赖 localStorage；
3. IndexedDB → localStorage → 内存 三级降级；
4. 每次变更自动下载 JSON 备份。

**结论**：选 3。`openStorage()` 探测一次并缓存结果；`loadTables/put*/delete*` 按模式分派；侧栏显示实际后端。

**代价**
- localStorage 是整库单键 JSON（`seat-planning:v2`），每次写都全量序列化；示例数据约 16 KB，接近 5 MB 配额时会失败并退化为内存（当前无超限提示）；
- 两个后端的数据不自动同步：在 A 浏览器用 IndexedDB 存的数据，换到禁用 IDB 的环境看不到，需要「全量备份/导入」；
- 自动下载备份没有采用：浏览器禁止无手势静默下载，且会造成大量文件。

**实测**（Edge 157，`file://`）：IndexedDB 模式刷新/重启进程后数据仍在；强制禁用 IndexedDB 后 localStorage 模式同样跨刷新/跨进程保留，HTML 复制到另一目录仍共享（同 profile）。

## ADR-07 稀疏单元格 + 稳定 seatId

**背景**
1 万格如果全量写 JSON 会很大；插删行列后座位 id 若跟着变，历史分配会错位。

**选项**
1. 二维数组全量存储；
2. 稀疏 `cells: { "r:c": cell }`；
3. 稀疏 + 坐标派生 id。

**结论**：选 2；`seatId` 在格创建时生成（`uid('seat')`），插删行列不重算。

**代价**
- 读取要处理缺失键（`cellAt()` 返回 `undefined`）；
- 复制/粘贴必须重新生成 `seatIds`（`cloneCell(..., regenerate=true)`），否则两个格共用 id；
- 座位 id 与坐标解耦，调试时不能从 id 反推位置。

## ADR-08 排号 = 行，座号 = 行内顺序，视角只改取座顺序

**背景**
旧模型从坐标反推排号，容易因元素错位产生歧义；主席台视角又需要左右换算。

**选项**
1. 排号/座号都持久化到单元格；
2. 排号/座号实时由行列计算；
3. 排号由行计算、座号由行内顺序计算，视角只影响排座取座顺序。

**结论**：选 3。`SeatRef.seatNo` 由 `seatsInRow()` 实时算出；`viewpoint` 只在 `arrange()` 里影响 `hallOrder`。

**代价**
- 座号无法人工指定（不支持「跳号」「自定义座号」）；
- 过道/禁用位不占号，与部分场馆的真实座号规则可能不同；
- 换来表格、座位图、导出三处编号永远一致。

## ADR-09 全新迁移，不兼容 v1 自由画布

**背景**
v1 数据是「元素 + 元素内座位槽」，与表格模型没有一一映射；迁移会有损且长期维护双模型。

**选项**
1. 写 v1→v2 迁移器；
2. 保留双模型运行；
3. 直接删除 v1 代码，新库 `seat-planning-v2`。

**结论**：选 3（用户明确要求）。旧代码 `ElementCanvas`、`layout/*`、`engine/grid.ts`、`engine/geometry.ts` 等已删除；不读取旧库 `seat-planning`。

**代价**
- 老用户的历史布局与排座结果不可用；
- 没有回退路径（只能靠旧版单 HTML 文件本身）；
- 换来数据模型单一、代码量显著下降。

## ADR-10 撤销用整表快照，不用命令模式

**背景**
表格操作种类多（合并、插删行列、填充、改宽高、批量设类型），命令模式要为每种操作写正向/反向逻辑。

**选项**
1. 命令模式（undo/redo 每条命令）；
2. 整表快照（每次提交存一份序列化状态）；
3. 只支持部分操作撤销。

**结论**：选 2，`useLayoutHistory.ts` 最多 80 份，快照为 `{ sheet, zones, canvas }` 的深拷贝。

**代价**
- 内存随表规模增长（30,000 格 × 80 份快照会很大）；
- 快照粒度是「一次 commit」，拖拽过程中不产生中间撤销点；
- 换来所有操作类型统一支持，新增操作只要 `historyPush` 即可。

## ADR-11 工作表上限 300×100，冻结最多 5 行/5 列

**背景**
无虚拟滚动，必须给 DOM 规模设上限；冻结行/列过多会让冻结覆盖层占满视口。

**结论**：`createSheet()` 与「表格设置」都 clamp 到 `300 × 100`，冻结 `0..5`。

**代价**
- 超大会场无法在一个工作表里表达（可拆多个布局）；
- 极限规模下交互卡顿（见 ADR-04 与 `known-issues.md`）；
- 换来可预期的性能边界与简单的实现。

## ADR-12 Excel 导出只出明细，不出图形

**背景**
用户需要把排座结果给不装本工具的同事看。

**选项**
1. 用 SheetJS 生成带样式的可视化座位表（合并单元格、填色、边框）；
2. 只导出「排号/座号/姓名/职级/单位/状态/锁定/区域」明细；
3. 只提供 PNG。

**结论**：选 2；可视化由 PNG 承担（`renderSeatChart`，3× 缩放）。

**代价**
- Excel 里看不到座位布局，需要与 PNG 配合使用；
- 明细是「一座位一行」，105 座就是 105 行（含空位），不是紧凑名单；
- 换来实现简单、字段稳定、方便二次筛选/透视。

## ADR-13 自研表格编辑器，不引入第三方表格库

**背景**
需要离线单文件、零外链，且交互只需覆盖「排座布局」这一垂直场景。

**选项**
1. AG Grid / Handsontable；
2. 自研 `SheetGrid`；
3. 使用 Excel 组件（如 Luckysheet）。

**结论**：选 2。

**代价**
- 选区、冻结、复制粘贴、键盘导航都要自己维护，边界 bug 需要自己修；
- 不具备公式、筛选、条件格式等通用能力；
- 换来包体可控（当前总产物约 1.29 MB）、无 License 约束、样式与业务语义（座位/主席台/特殊块）深度贴合。

## ADR-14 布局编辑页用 CSS transform 缩放，坐标统一除以 scale

**背景**
表格是 DOM 绝对定位，直接改行列尺寸会破坏真实尺寸；缩放必须只影响显示。

**结论**：滚动内容外包一层 `.sg-space`（尺寸 = 逻辑尺寸 × scale），内层 `.sg-inner` 用 `transform: scale()`，`transform-origin: 0 0`。冻结行列、选区、编辑框都在缩放层内；鼠标坐标先判断冻结区，再 `(像素 + scroll) / scale` 还原为逻辑坐标；列宽/行高拖动增量同样除以 scale。

**代价**
- 表头文字不随缩放变小（只缩放位置与宽度），极端缩小下表头会显大；
- 缩放状态不持久化，换布局后回到 100%；
- 换来零重排、缩放不丢选区与排座结果。

## ADR-15 预设 = 布局快照，表存 IndexedDB 独立 `presets`

**背景**
预设要能跨布局复用，同时不能影响已排座项目的座位 id。

**结论**
- `LayoutPreset` 保存一份完整 `LayoutPackage` 快照；
- 从预设新建时复制快照、换新布局 id，并重新生成全部 `seatId`，避免与来源布局串座；
- 2 套内置模板不写库，每次从代码生成，删除按钮对内置模板隐藏；
- 整包导出只包含布局；预设随「全量备份」一起迁移。

**代价**
- 预设是快照，源布局后续修改不会同步；
- 预设体积与布局相同，数量多时备份文件变大。

## ADR-16 导入解析零新增依赖，Word 走自研 ZIP + `DecompressionStream`

**背景**
需要读 Excel / Word / CSV，但离线单文件包要尽量小，不能为了 .docx 引入 mammoth/jszip。

**结论**
- Excel 复用既有 SheetJS；
- CSV/TXT 自写引号感知解析器，UTF-8 失败回退 GBK，分隔符在逗号/制表符/分号/中文逗号中取样；
- `.docx` 只读 `word/document.xml`：自写 ZIP 中央目录读取，deflate 用浏览器原生 `DecompressionStream('deflate-raw')`，再用 DOMParser 按段落/表格行抽取；
- `.doc` 旧二进制格式明确拒绝并提示另存；
- 姓名解析覆盖序号、括号备注、空格/短横线后缀、性别、电话、多人并列。

**代价**
- 依赖 Chromium 的 `DecompressionStream`（Tauri WebView2 / 现代 Edge 均可用），老浏览器会给出明确提示；
- 不解析 Word 页眉页脚、文本框、批注；
- 换来零新增依赖、包体不膨胀。

## ADR-17 自动保存 900ms 防抖 + 切换/关闭兜底

**背景**
原先只有手动保存，刷新或切页会丢草稿。

**结论**
- 布局、名册、项目三处都在变更后 900ms 自动落盘；
- 切换实体前先 flush 当前草稿；删除实体前先取消待执行的自动保存，避免「删了又被写回」；
- `beforeunload` 在仍有未保存变更时提示；
- 手动保存会取消待执行的定时器。

**代价**
- 高频编辑时每 900ms 可能写一次整库（localStorage 模式是全量序列化）；
- 自动保存没有可见的成功提示，仅在页脚保留脏标记/保存按钮。

## ADR-18 导出按 12000px 上限自动降倍，默认配色与界面一致

**背景**
大布局 4× 导出会超过 Canvas 尺寸上限，浏览器可能直接产出空白图；同时导出图与界面配色需一致。

**结论**
- 导出倍率可选 2×/3×/4×，打印可选 A4 横向/纵向；
- 按 `12000 / 画幅` 计算可用倍率并自动下调，toast 告知实际倍率；
- Canvas 渲染同步界面配色：普通座位浅墨青、主席台加深、未排座虚线、固定空位斜纹、已排座左侧职级色条、请假暖黄。

**代价**
- 极端大布局可能只能 1× 左右输出；
- 斜纹是自绘 pattern，打印分辨率下纹理较细。

## ADR-19 预设与备份的版本口径

**结论**
- `LayoutPackage.schemaVersion` 仍为 `2.0`；
- 全量备份升级为 `2.1`（新增 `presets` 字段），导入同时接受 `2.0` / `2.1`，更高版本直接拒绝并提示；
- 导入按 id `bulkPut`/`upsert` 合并，不静默清空本地数据；
- 导入结果返回各表写入数量与结构告警。

**代价**
- 同 id 记录会被备份覆盖；
- 没有「导入前自动备份」步骤，误覆盖只能靠事先手动导出。

## ADR-20 会场编号、座位详情浮层与「请假」口径

**背景**
用户要求：布局页顶部列标改数字；每排座位号按排座算法顺序（中间为 1、左右交替向外），而不是从左到右顺排；点座位从上方/下方弹卡片；请假人员不参与排座，但在右侧单独列出，名册里可切换「在位/请假」。

**结论**
- 列标统一为数字（`1..N`），布局页选区标识改为「N 列 M 行」，不再使用 `A1:B2` 形式；`colLabel()` 已删除。
- 新增 `seatOrderMap(layout, rules)`：主席台排用 `podiumOrder`，台下用 `hallOrder`，按算法落座顺序给每排座位编号；座位物理位置不变，只改显示编号。座位图、详情卡片、Excel 导出共用同一份编号。
- 座位详情改为 `Teleport` 到 body 的浮层卡片：锚定被点座位，优先向下，空间不足翻到上方；滚动、滚轮缩放、窗口尺寸变化时用 `requestAnimationFrame` 重新定位；点击外部、再点同一座位或 Esc 关闭；打开时焦点进入卡片，Esc 关闭后焦点回到座位。
- 请假改为人员级状态 `Member.status: 'present' | 'leave'`，不再写入 `Assignment.status`。排座时直接排除请假者，统计里请假只计数、不占座；右侧新增「请假」tab，名册页提供「在位/请假」切换。
- 备份 schema 升为 `2.2`，导入兼容 `2.0/2.1/2.2`；旧数据 `active:false` 迁移为 `leave`，旧备份里请假者的座位安排在载入/导入时清理。
- 移除 `RuleSet.podiumLeave`（留空位/前移）——请假者根本不入座后该规则没有意义，规则面板改为静态说明。

**代价**
- 主席台偶数座位时「1 号」是中间两人里靠左的一位；遵守「以左为尊」时 2 号会出现在观众视角的右侧，和台下「中间偏左为 1、偏右为 2」的观感不完全一致，这是两套既有规则的直接结果。
- 关闭页面再打开时浮层不会恢复（座位选中状态不持久化）。
- 旧版项目中状态为「停用」的人员会被理解为请假，而不是从名册中删除。

## ADR-21 工作台分区、状态归属与座位配色

**背景**
用户指出：布局页左侧布局列表应改成顶部一行 tab；布局页与排座项目页的生硬竖线应改为淡背景分区；交换座位时两个座位都要高亮；「在位/请假」应设在排座项目里而不是名册页；整体设计需要一次完整审核（信息层级、留白、控件形态、座位状态可读性、操作动线）。

**结论**
- 布局页删除左侧 `lv-rail`，布局列表改为顶部一行 tab（激活项白底细边，其余透明），新建按钮紧随其后；「存为预设 / 从预设新建 / 导出全部 / 删除」收进同一行右侧。布局名称不再在工具栏重复。
- 新增令牌 `--bg-sunken: #f5f7f7`，用于右侧详情面板、布局 tab 条等「分区底色」；排座项目右侧面板取消 `border-left` 与卡片描边，改为淡底色 + 圆角，和座位图之间靠色差分层。
- 交换座位时：拖拽源座加 `is-drag-source`（虚化）、目标座加 `is-drag-over`（虚线框）；落座交换后两个座位同时加 `is-flash` 高亮 950ms。`prefers-reduced-motion` 下改为静态描边。
- 「在位/请假」只在「排座项目 → 名单」每行切换；请假 tab 提供「恢复在位」。名册页的状态列改为只读标签，表单不再编辑状态。切换为请假会立即从当前项目分配中移除并保存名册/项目，避免刷新后残留。
- 座位配色加强区分：已排座 `#e7f1f0` + 描边 `#b6d1cf`，空位白底虚线，主席台 `#d9e9e7`，固定空位斜纹，锁定/请假用暖色；图例色块同步。
- 布局编辑器去掉逐格重复文字：同名桌带每排只显示一次桌名，删除每格重复的「双人位」（两个圆点已表达座位数），降低网格噪声。

**代价**
- 请假只能在打开某个排座项目时操作；只改名册不建项目时无法标记请假。
- 顶部 tab 在布局很多时会横向滚动，没有下拉总览；左侧原有的常驻列表不再可见。
- 两个座位的高亮依赖动画结束自动清除，快速连续换座以最后一次为准。

## ADR-22 布局由「列表」承担，预设概念下线；编号取消镜像；区域可反向查看

**背景**
用户连续提出：布局顶部改成「当前布局 + 切换/新建 + 管理菜单」；预设这套概念不再需要；排座编号以就座者自身左右为准；区域要能反向定位和高亮；主席台/普通位容量不能只限 1–2 人；左侧不应再有描边线。

**结论**
- **布局切换**：顶部左侧只显示「当前布局：名称」，右侧是「切换」「新建」两个按钮 + 「管理布局」齿轮菜单；菜单含重命名、复制为新布局、删除（二次确认）。「存为预设 / 从预设新建 / 存为预设」入口全部移除，`LayoutPreset`、`presets` 表与备份中的 `presets` 字段不再使用（旧备份仍可读取并忽略该字段）。ADR-15 作废。
- **编号方向**：删除 `RuleSet.viewpoint` 与所有镜像逻辑。主席台与台下统一使用 `centerOutOrder()`：1 号居中，2 号紧邻其右侧，3 号紧邻其左侧，4 号在 2 号外侧……双人桌偶数座时也保证 3 号回到 1 号**另一侧**（此前会把 3 号排到 2 号外侧，导致与 1 号同侧）。ADR-08 的「视角只影响取座顺序」改为「不设视角，编号只由座位左右关系决定」。
- **容量**：`SheetCell.seats` 由 `1 | 2` 放宽为 `number`（1–50，`clampSeats()` 归一化），助手栏与属性面板都提供「单人位 / 双人位 / 自定义 N 人」；`seatsInRow()`、导出 PNG、座位图、Excel 明细全部按 N 个座位槽展开，合并块与主席台同样适用。
- **区域反向查看**：属性面板的区域列表改成可点击的行，显示每个区域的格子数；点击后画布以「淡色填充 + 主色虚线」高亮该区域全部格子，再点取消。区域的分配/解除仍走 `historyPush` 快照，Ctrl+Z 可恢复到分配前状态，并新增「清除选区归属」。
- **区域人员分配**：新增 `RuleSet.zoneRules`，支持按级别快捷指派（多级别并集）、排除级别、手动勾选人员；引擎里手动人员最先落位，其次区域级别规则，最后才轮到职级分层；冲突写入 `warnings`。UI 在规则面板内提供影响人数预览与「撤销上次区域修改」。
- **视觉**：全局左侧栏去掉 `border-right`，改用 `--bg-subtle` 淡底色；名册姓名后补「级别 · 单位」。

**代价**
- 旧项目缺少 `zoneRules`，载入时补空数组；旧数据里的 `viewpoint` 字段被忽略，不会做迁移；
- 预设下线后，跨布局复用只能靠「复制为新布局」；
- 自定义容量上限 50，超大主席台（如百人长条）需要拆成多格；
- 区域规则与职级分层同时存在时只提示、不阻止，最终以区域规则为准。

## ADR-23 排座项目冻结名册快照；职务只展示不排序；名册顺序手动决定

**背景**
用户指出：人员名册会周期性变化（换单位、职级升降、调入调出），排座项目一旦排好就不应被名册变动自动改写，否则每次改名册都会把已排好的会场打乱。同时需要「职务」信息用于展示与筛选，但不能因为职务变动影响排序；名册顺序也必须由用户手动决定，系统不做自动排序。

**结论**
- **快照解耦**：项目创建时把当前 `RosterPlan` 深拷贝到 `Project.rosterSnapshot`。`rosterOf(project)` 优先返回快照，排座引擎、座位图、名单、导出全部读快照。名册后续增删改、排序调整都不会自动作用到项目；旧项目载入时补快照，已有座位分配保留。
- **手动更新差异清单**：项目「名单」提供「手动更新」入口，将当前名册与快照比对，按「单位变更 / 职级调整 / 职务变更 / 已不在名册 / 新增人员 / 顺序调整」分组；默认全选，可逐项勾选后应用。应用才写入快照，并提示「名册快照已更新，建议重新排座」；未应用时项目顶部显示「名册已变化，N 项待更新」。
- **顺序差异聚合**：排序变化不逐人罗列，只生成一条「顺序调整」聚合项；应用时只按双方共有成员重排快照，快照独有成员保持末尾，避免把已移除人员重新排进来。
- **职务字段**：`Member.duty` 支持新增/编辑、批量添加与 Excel/CSV 导入（表头匹配「职务 / 职位 / 岗位」），可在名册与项目名单中搜索、筛选。职务**不参与排序**，不引入职务序列、不做前后加权。
- **手动排序**：名册表格整行可拖拽（顶部手柄列），按行中点判定插入到前/后并显示落位线；落位立即改 `members` 数组顺序并提示保存。筛选状态下禁用拖拽，避免可见顺序与完整数组索引错位。顺序持久化，排座时作为同职级同单位内的先后依据。
- **展示分层**：座位格内空间有限，仍只显示「姓名 + 职级·单位」；职务在排座项目名单行（标签）与座位详情卡（独立一行）完整展示。

**代价**
- 项目与名册彻底解耦后，名册更新不会自动同步；用户必须主动打开差异清单确认，忽略的差异会持续提示。
- 顺序变化只能整体应用或整体忽略，不支持只应用部分人的相对顺序。
- 拖拽排序依赖完整列表，筛选态不可拖动，需要先清除筛选。
- 职务为自由文本，不做字典校验；同名职务的不同写法（如「主任」「主任委员」）会分别出现在筛选项里。

## ADR-24 座位槽等分所在格；只读排座图不画区域名；职级用淡底而非色条

**背景**
排座图的座位槽原先在格内预留 4–8px 缝隙，形成「小卡片」观感；合并主席台仍渲染「主席台」区域名，压住第一名人员；每个已排座格左侧画 2px 职级色条，且格内同时显示单位，导致双人位出现「副科级 · …」截断。

**结论**
- `seatsInRow` 的槽位严格按 `rect.w / n` 等分，`y/h` 占满整格，不再留缝。合并主席台 N 个座位即 N 等分，导出与界面共用同一几何。
- 只读模式（排座图）不渲染桌名/区域名，座位内容独占整格；编辑/布局页仍保留名称与座位圆点。
- 已排座格去掉左侧色条，改用职级色 9% 的极淡底色区分；空位透明，保留固定空位/过道的斜纹底。
- 格内只显示「姓名 + 职级」，姓名与职级允许换行；单位、职务仅在名单与座位详情卡展示。

**代价**
- 合并块内没有分隔线，N 等分只能靠底色差异与姓名等距排布感知；同职级相邻时边界更弱。
- 只读图不显示区域名，识别主席台位置依赖布局上下文与座位编号。
- 极窄双人位中长姓名仍可能换成两行，但不会再出现「职级 · …」残句。

## ADR-25 边框整表去重 + 设备像素对齐；座位序号开关随项目保存

**背景**
默认边框对每个座位/主席台矩形独立描边，相邻格共享边被重复绘制；显式边框再叠一层。`non-scaling-stroke` 让线宽不随缩放变化，但重叠描边在亚像素位置会加深或发虚。更隐蔽的是座位按钮的淡色底画在边框之上，按亚像素随机盖掉一部分线，导致同图线条粗细不一。

**结论**
- 边框只在引擎层收集一次：`collectBorderLines` 按「同一直线上的区间」切分，每段只保留一条（显式优先、其次默认），界面与导出共用。
- 线宽与坐标都在绘制前换算到设备像素：奇数线宽对齐 `k+0.5`、偶数对齐 `k`，`stroke-width = width / scale`，不依赖 `non-scaling-stroke`；外圈允许溢出 0.5px，避免被 SVG 视口裁细。
- 边框 SVG 置于座位叠加层之上（`z-index: 4`），不再被座位底色覆盖。
- 序号是项目级显示偏好：`Project.showSeatNumbers`，缺省 true；画布与导出读取同一值，导出序号取与画布相同的座位顺序。

**代价**
- 边框几何每帧随缩放重算并逐条输出 `<line>`，节点数约为边数的 1–2 倍（千级座位仍在毫秒级）；换来的是可预测的 1px 观感。
- 边框压在姓名上层，极窄格里线可能擦到文字边缘（线本身在格边界，不遮挡正文）。
- 序号开关只影响显示，不改变座位顺序数据。

## ADR-26 布局操作栏只留高频动作；容量归属性面板；默认黑框可显式覆盖；辅助网格只在编辑态

**背景**
布局页操作栏原先把「座位规格（单人/双人）」和「边框」都做成常驻按钮组，挤占横向空间；边框样式入口以文字形式出现，与行列/合并/类型平铺；编辑态缺少整表参考线，空表时难以判断行列边界。

**结论**
- 操作栏删除「座位规格」整组：座位容量改由右侧属性面板统一负责，单格/多选都作用于当前选区。
- 边框收为单个图标按钮 + 下拉：快捷边框、线型、粗细、线色都在下拉内完成，不再占用常驻宽度。
- 座位/主席台默认绘制黑色 1px 实线；用户显式设置某几边时，该格不再叠默认框，只画选中的边。
- 快捷边框是「切换」语义：选区已具备该组边时再点一次等于取消，取消的做法是删掉 `style.borders` 字段、回落到默认黑框；「清除边框」才写空数组 `borders: []`，表示该格显式无框。两者不再等价。
- 快捷边框 7 个按钮按当前选区实时回显选中态：四边齐全→「外 + 内」，仅外圈齐全→「外边框」，否则按齐全的单边点亮；`borders` 为空数组时点亮「清除边框」。
- 编辑态恢复整表淡虚线辅助网格（合并块内部不画），只读排座图与导出图不绘制；导出仍只输出 `collectBorderLines` 的真实边框。
- 主席台文字改成与普通座位同一量级（12px、主文字色），不再按块尺寸放大。

**代价**
- 容量入口从「选中即可见」变成「右侧面板可见」，窄屏下需要滚动属性面板。
- 显式边框是整格覆盖语义：只设左边框会去掉该格其余默认边，需要用户主动补全。
- 辅助网格在密集表上会增加视觉噪声，但密度受缩放影响，且不进入导出。

## ADR-27 本地数据管理收口到「设置中心」；座位姓名两端对齐；名单导出按在位口径

**背景**
左下角原本是三行存储说明文案，用户无法在应用内查看数据量或清理数据；全量备份/导入散落在「排座项目 → 导出与备份」里，与导出 PNG/Excel 混在一起。座位格内姓名只用居中/左对齐，两字名与三字名两侧留白不一致。排座结果的 Excel 明细包含空位与请假，不适合直接作为「在位人员名单」上报。

**结论**
- 左下角改为「设置中心」入口，面板内展示各表条数与 JSON 体积、总占用、存储位置；提供导出全量备份、导入备份、清空数据（二次确认）三项操作。
- 「排座项目 → 导出与备份」删除全量备份/导入备份按钮，只保留 PNG / Excel / 在位人员名单 / 打印，避免两套入口。
- 清空数据后以 `loadAll(false)` 重新读取，不自动灌入示例数据；示例数据只在首次空库启动时生成。
- 座位姓名在画布用 `text-align-last: justify` + `text-justify: inter-character`，导出按字符宽度均分剩余空间逐字绘制，做到首尾贴边、字距均匀。
- 新增「在位人员名单」Excel：姓名 / 职级 / 单位 / 职务 / 座位号 / 区域，跳过固定空位、空位与请假人员。

**代价**
- 数据体积用序列化字节数估算，与 IndexedDB 实际磁盘占用存在差异，但足以判断量级。
- 两端对齐会让两字名中间留出较大字距，属于用户明确要求的效果。

**修订（2026-11-10）**：容量入口已从布局属性面板整体移除，改由排座项目设置；见 ADR-28。

## ADR-28 桌容量归排座项目，布局页只定义位置

**背景**
会场布局描述的是「固定会场形状与桌椅位置」；一张桌坐几人属于每次会议的实际安排。ADR-26 把容量放进布局属性面板，导致同一份会场要按不同会议反复改布局，且共享布局会被排座项目污染。

**选项**
1. 容量留在布局属性面板；
2. 容量写回布局的 `seats` 字段并让项目只读；
3. 布局保留旧 `seats` 作为兜底，项目用 `seatCapacity` 覆盖并派生 Sheet。

**结论**
- 选 3。`Project.seatCapacity`（`"行:列" → 人数`）由排座项目维护，`applySeatCapacity` 返回派生 Sheet，不改共享布局；旧布局的 `seats` 继续可读。
- 布局页删除所有容量入口（属性面板、操作栏、右键菜单、填充对话框），只保留桌位/合并/区域/尺寸/样式；属性面板与填充对话框各留一句「一桌坐几人请在排座项目中设置」。
- 单格、选区批量、自定义 N 人都在排座项目内完成；缩容时被移出的人员会集中提示。

**代价**
- 旧布局的 `seats` 与项目覆盖可能不一致，需要 `applySeatCapacity` 做兼容；
- 布局页不再能直接看到「这张桌能坐几人」，只能通过座位点数量间接判断。

## ADR-29 画布平移直接用滚动值，不用变换矩阵

**背景**
两个画布都支持缩放，中键拖动需要任意比例下都对位。若通过 CSS transform 平移，需要把屏幕位移换算回画布坐标，缩放变化后容易累积误差。

**结论**
- 中键 `pointerdown` 记录起点与 `scrollLeft/Top`；window `pointermove` 直接按指针位移增量改滚动值。滚动单位就是视口像素，缩放只影响内容尺寸，天然对位。
- `pointerdown` 上 `preventDefault()` + `auxclick/mousedown` 阻止中键自动滚动；`.is-panning` 统一 `grabbing` 光标并禁用选择；`pointerup` / `pointercancel` 解绑。

**代价**
- 平移依赖滚动容器，若未来改成无限画布需重写；
- 中键事件在部分触控板驱动下可能缺失，保留空白区域拖拽等其他方式。

## ADR-30 设置中心改为独立页面，按数据库视角呈现

**背景**
ADR-27 把设置中心做成左下角弹层，信息密度低，也无法容纳逐表统计与风险说明。

**结论**
- 左侧导航新增「系统 / 设置中心」，与「名册与组织 / 会场布局 / 排座项目」同级；原底部弹层入口删除。
- 页面按表列出记录数、占用与占比，顶部给总占用、存储位置与持久化状态；备份/导入/清空放在右侧操作列。
- 清空使用模态二次确认，逐项列出会被删除的数据量，明确「无法撤销，只能通过备份恢复」，并提供「先导出备份」。

**代价**
- 设置从「随时点开」变成「切换页面」，但信息量与风险提示更完整；
- 数据体积仍按 JSON 序列化估算，与 IndexedDB 实际磁盘占用存在差异。

## ADR-31 座位信息行改为用户自选开关；姓名恢复居中

**背景**

**代价**
- 三行信息在低缩放或小格子里会以省略号收尾，需要放大查看；

## ADR-32 规则面板用「职级多选弹窗」替代两套胶囊

## ADR-33 容量操作以「点选时的桌」为准，预设与数字框互相同步

**背景**
座位槽数量变化后旧 `seatId` 可能失效，详情卡若只依赖 `seatIndex.get(seatId)`，标题会退化为「座位」、`selectedCellKey` 为空，点「应用」静默无效；同时预设高亮只看当前容量，输入自定义值时仍误亮「单人 / 双人」。

**结论**
- 点选座位时把 `row/col` 一并存下并随 `pick` 事件传出；`selectedCellKey`、标题、容量读取都以「当前 id → 点选时的桌」两级回落。
- 容量变化后若选中 id 失效，自动改选该桌第一个座位，卡片不脱锚。
- 预设按钮高亮由数字框 `capCustom` 驱动（输入即同步、自定义值取消预设），应用统一做 `clampSeats` 收敛并给出 toast。
- 缩容只移除确实消失的座位槽上的分配，提示被移出人员姓名；`flash` 复用单一定时器，避免旧定时器擦掉新提示。

**代价**
- 详情卡多依赖一份点选行列状态；切换项目/关闭卡片时需一并清理。

## ADR-34 取色预览不进历史，提交时只记一步

**背景**
样式面板使用原生取色器，拖动过程连续派发 `input`；若沿用原有「每次改动即 `historyPush`」，一次调色会生成大量撤销步，且预览阶段就会污染历史。

**结论**
- `input` → `preview-style`：只改模型并 `markDirty()`，不写历史；`change` → `style`：调用一次 `commit()`。
- 快照历史天然满足「一次调色一步撤销」：预览期间 `hIndex` 停在调色前，提交后追加最终快照；无实际变化时 `historyPush` 因快照相同自动去重。
- 预览对当前选区（含多选）逐格套用，底色与文字色分别对应各自属性。

**代价**
- 拖动超过自动保存间隔时中间态可能被落盘，但撤销仍以提交后的单步快照为准。

## ADR-35 批量容量用「空白起手框选」，选框画在视口层

**背景**
批量容量原先只能逐桌点选。画布本身已有单击看详情、拖拽换位两种指针交互，加框选必须避免手势冲突，且画布支持缩放与滚动，选框坐标不能只在按下时算一次。

**结论**
- 框选只在批量容量模式生效；指针按下用捕获阶段监听在面板根节点，命中座位、行列头、底栏缩放控件、原生滚动条一律放行给原有交互。位移不足 4px 视为单击空白（清空选区）。
- 选框用视口坐标绘制在面板根节点（`position:absolute` + `pointer-events:none`），不进入缩放层，避免被 `transform: scale()` 二次缩放。
- 每次 `pointermove` 用缩放层的实时包围盒把「按下点」重新换算成工作表坐标，因此拖动中滚轮滚动、或滚动后重新框选都不会错位；选择判定按每格座位包围盒并集与矩形求交。
- Ctrl/Meta 由 `pointerup` 上的修饰键决定追加或替换；Esc 与空白单击清空。
- 容量应用沿用 `setCapacity`，缩容提示、撤销与持久化逻辑完全复用。

**代价**
- 空白起手意味着座位铺满的区域无法直接起手，需从桌间空隙/画布留白开始；
- 拖动中不自动滚动，需要用户自行滚轮移动画布。

## ADR-36 历史快照可批量清理，但永不参与运行时引用

**背景**
排座前自动留存的快照越积越多，用户希望能在项目内多选删除、在设置中心一键清空，同时担心误删影响正在使用的数据。

**结论**
- 快照只是「排座前版本」的独立记录，项目、名册、布局、预设都不持有快照 id，恢复操作是把快照内容拷回项目，因此不存在「正在被使用」的快照，可以任意删除。
- 既然没有保护对象，就不做「禁止删除基准快照」的硬限制，而是把删除后果写进确认文案：删除后无法恢复到这些旧版本，当前排座结果与实体数据不受影响。
- 项目内删除走通用确认弹窗（可撤销前二次确认）；设置中心一键清空走独立弹窗，必须列出条数、可释放空间、影响范围与不可撤销，避免误触。
- 清理只调 `deleteSnapshots` / `clearSnapshots` 两张表的删除，不触发 `loadAll` 之外的实体数据写入；设置中心清空后重新统计，保证记录数与占用即时刷新。

**代价**
- 快照列表改为全量展示（可滚动），条目极多时需要滚动查找；
- 清空是全局操作，会一并清掉所有项目的历史快照。

## ADR-37 下拉弹层统一走 useAnchoredPopup，选项单行且不内部滚动

**背景**
触发器分散在侧栏、工具栏和缩放容器内，历史上各自算坐标：有的相对最近定位祖先生成，有的把弹层挂到带 transform 的容器里，缩放后坐标被二次变换，出现向下偏、左边缘不齐、压住统计条。选项又把名称和「30 人」拆成两行，列表过高。

**结论**
- 弹层一律 Teleport 到 body，定位用 position: fixed + `getBoundingClientRect()`，与触发器同处视口坐标系，不受祖先 transform/overflow 影响。
- 统一 gap 4px、左对齐、宽度取 `max(触发器宽, minWidth)`；下方空间不足且上方更宽时向上翻转；打开期间监听 scroll(capture)/resize/visualViewport/ResizeObserver 实时重算，而不是关闭弹层。
- 选项只保留必要文字，名称单行 32px 高，文字溢出省略；不提供 `hint` 副信息。正常条目数靠精简文案与紧凑行高一次展示完，不出现滚动条。
- 高度兜底：弹层上限按视口可用空间动态计算（上下各留 12px，最多取可用空间的 90%）；上下都放不下时选空间较大的一侧，弹层不超出视口。只有内容超过兜底上限的极端情况才出现内部滚动（`overflow-y:auto` 仅在封顶时写入）。窗口 resize / 缩放 / 触发器尺寸变化后重新计算上限。

**代价**
- 极端条目数会触发内部滚动（仅在内容超过视口兜底上限时），与「正常条目数不滚动」的目标不冲突。

## ADR-38 元素与单元格解耦：几何独立存储，锚定模式只决定换算方式

**背景**
讲台、人形、门等需要任意摆放，但用户又希望部分元素随行列增删移动。若把元素做成单元格类型，就回到「元素跨格 = 合并」与「单元格 = 座位」冲突的老问题。

**结论**
- 元素始终保存自己的宽高、旋转和锚点描述；`anchor.mode='cell'` 时用覆盖行列 + 比例偏移换算，`free` 时直接用绝对坐标。渲染层只认 `resolveGeometry` 的结果。
- 属性面板切换锚定方式时做双向换算（`anchorToCell` / `anchorToFree`），保证切换瞬间视觉位置不变。
- 拖动/缩放元素时先固化为 `free` 以获得连续反馈，松手后再按当前几何反推覆盖行列重新锚定，避免交互过程中被行列吸附拉扯。
- 行列增删只平移 `cell` 锚点（`shiftElementAnchors`），`free` 元素保持绝对位置。

**后续（2026-11-10）**

- 面板不再暴露锚定切换：新元素一律浮于单元格。`cell` 模式保留为**旧数据读取通道**（`normalizeElements` / `resolveGeometry` 仍能还原原位置），`anchorToCell` 仅内部保留，不再有 UI 入口。

**代价**
- 固定单元格元素在行列被整体删除时可能失去绑定行列，需要 `normalizeElements` 夹取到有效范围。

## ADR-39 元素图形由一份 SVG path 驱动画布、预览与导出

**背景**
元素库预览、画布渲染、Canvas 导出如果各画各的，图形会漂移，导出与屏幕不一致。

**结论**
- 每个元素在 `ELEMENT_SHAPES` 中定义 100×100 坐标系下的填充路径与细节线；元素库预览、`SheetElementLayer`、`engine/render.ts`（Path2D）共用。
- 选中框、旋转柄、缩放手柄只在可编辑画布出现；只读排座图关闭 pointer-events，避免遮挡座位点击。
- 讲台默认 `bordered: false`，符合「讲台是一个无边框形状」的要求；其它元素按用途给默认描边。
- 文字样式（字号、颜色、字体族）落在元素数据上，画布与导出读同一份字段。

**代价**
- 新增元素必须同时提供 path 与默认元数据，否则预览与画布会退化；已在 `ElementKind` 上做类型约束。

## ADR-40 属性面板共用一套演算规格，文字位置进入元素数据

**背景**

元素面板、选区面板、排座规则面板由不同轮次拼出来：分区标题分别是 10.5px / 11px / 12px，控件高度 26–28px，圆角 4–5px，选区面板还用原生 checkbox 与原生取色器，点开字体还能看到浏览器原生 select。用户把三个面板摆在一起时能一眼看出不是一套东西。同时元素文字此前只能居中，无法像 PPT 一样调位置。

**结论**

- `style.css` 提供唯一一份 `.insp-*` 规格：面板内边距 12px、分区标题 12px/600/`--text-secondary`、标签列 40px、控件高 28px、圆角 `--radius-xs`（6px）、字号 `--fs-xs`（12px）、开关 34×20、色板 21px（文字色 18px）、快捷按钮 24px、操作按钮 28px、分区之间用 `--border-soft` 分隔。
- 两个属性面板根节点共用 `.insp-panel`；三个面板的分区标题共用 `.insp-title`，规则面板保留编号圆点。
- 所有下拉必须是 `UiSelect`（与「名册方案 / 会场布局」同一组件），禁止原生 `select`；开关、色板、分段控件同样走共用类名。
- 快捷说明不再常驻底部：收进 `<details class="insp-keys">`，默认折叠。
- 文字位置作为元素数据的一部分：`textAlign`（左/中/右）、`textVAlign`（上/中/下）、`textOffsetX/Y`（工作表单位）。画布用 flex 对齐 + `translate`，导出用 `textAlign` / `textBaseline` + 相同内边距与偏移；`elementTextPadding()` 统一两侧留白，人形缺省贴底。

**后续（2026-11-10 复核）**

并排复查又清掉三处残留，以下三条此后为唯一规格：

- **色板只有一种形态**：`.insp-swatch` 与 `.insp-color` 都是 20×20、圆角 5px 的方块，不再有圆形或 18/21px 的变体；文字色、填充色、选区面板两套色板、自定义取色入口全部同形同尺寸。自定义取色不再暴露原生控件外形，用 conic-gradient 底 + 透明 input 覆盖。
- **次要按钮只有一种形态**：`.insp-quick button` 与 `.insp-actions .insp-btn` 均为 28px 高、6px 圆角、`--border-strong` 描边、12px 字号；不再出现纯文字链或行内 24px 小按钮。「清除底色」「清除选区归属」「＋ 新建区域」「偏移归零」都走这一形态。
- **说明只有一种入口**：面板内不常驻小号灰字。需要解释的内容统一收进底部 `<details class="insp-keys">`（12px、行高 1.6、默认折叠），元素面板叫「快捷键」，选区面板叫「提示」。

**代价**

- 三个面板不再各自定义标题与控件样式，调整规格必须改全局 `.insp-*`；这是有意的约束。
- 文字对齐的 CSS 与 Canvas 两套实现需要保持同一套内边距/偏移公式，新增对齐方式时两边都要改（helpers 已集中在 `engine/elements.ts`）。

## ADR-41 取色统一走 UiColorPicker + 全站唯一预设

**背景**

属性面板里形成了「预设色块 + 藏在色块里的自定义取色」，但职级、区域、边框线色仍是各写一套：职级是 18px 圆点且没有自定义取色，边框是圆形色点 + 虚线圆，单元格/元素又各自维护色块数组。用户要求全站统一，并保证职级标识色改名册、座位图、图例、导出图片一致。

**选项**

1. 保留各处色板，只把尺寸调成一样；
2. 抽一个 `UiColorPicker`，各入口直接复用，色板数据全局唯一；
3. 用现成第三方取色库。

**结论**：选 2。

- `src/ui/colorPalette.ts` 提供唯一 5 色预设（`#E8EEEE` 浅底 + `#C2A079` / `#4A7C7B` / `#B4483F` / `#3D5A6C` 四个标识色），固定排成一行；任何入口不再自带数组。
- `src/ui/components/UiColorPicker.vue` 统一 20×20、圆角 5px；自定义入口是同尺寸 conic-gradient 方块，原生 `<input type="color">` 以 `opacity: 0` 覆盖，仅作为系统取色弹窗的触发器，页面不出现原生控件外观。
- 清除/恢复默认是组件能力：`allowClear` 显示同尺寸斜杠按钮，`clear` 事件由调用方决定「清空」还是「回落默认色」。选区面板「清除底色」因此从独立文字按钮收进组件，不再有第二套样式。
- 提交语义分两级：`update:modelValue` 用于实时预览，`change` 用于写撤销历史；点预设同时触发两者，拖系统取色器只在确认时触发 `change`。
- 职级色一致性：项目名册仍按创建时冻结快照提供成员与单位，但展示/导出使用 `displayRoster`，职级颜色按 id 取当前名册的最新值；`seatInfo`、座位图 `--rank`、名单圆点与 `renderSeatChart` 全部消费这一份颜色。这样既不改历史成员快照，也不会出现「名册改了颜色、座位图和导出还是旧色」。

**代价**

- 5 色是折中集合：单元格浅底色与职级深标识共用一套，某些场景可选项不如专用色板多。需要更多颜色时走自定义取色，而不是再加一套数组。
- 组件内仍保留一个原生 `input[type="color"]`（不可见）；这是获得系统取色器的唯一可靠方式，探针以「组件外原生 input 数量为 0」作为约束。
- 项目职级颜色改为实时读取后，若当前名册删除了某个职级，快照里的旧职级仍保留原色（找不到同 id 时不覆盖）；这是有意的兜底。

## ADR-42 数值输入统一走 UiNumberInput + 边框分组

**背景**

属性面板的边框行把开关、线宽下拉、取色器全部塞进 172px 的控件列，取色器被压到 0 宽后内部换行，视觉上重叠并压到下一行。数值输入则直接使用 `input[type="number"]`，原生 spinner 在面板里显得突兀，单位 `px/°/人` 以裸文本飘在框外，宽度与对齐各写一套。

**选项**

1. 继续用原生 number，只隐藏 spinner，逐处调单位位置；
2. 抽一个 `UiNumberInput`，统一宽度、单位、步进与焦点态；
3. 引入第三方数值控件库。

**结论**：选 2。

- `UiNumberInput` 用 `type="text"` + `inputmode="decimal"`，从根上没有原生 spinner；单位固定在框内右侧，输入区左对齐；默认 64px，规则区间 46px，紧凑容量 56px/24px。
- 步进两条路径：↑/↓ 与鼠标滚轮。滚轮只在输入框聚焦时接管，否则让页面正常滚动；Enter/失焦提交，提交时按 min/max 与小数位钳制。
- 聚焦态直接复用 `.insp-input` 的主色描边与 3px 光晕；`role="spinbutton"` 保留无障碍语义。
- 边框区改为「开关一行 → 线宽一行 → 颜色一行」：开关行只保留开关与「显示/无边框」状态；线宽不再用下拉，改为可精确输入的数值控件；颜色行独占控件列，7 个 20px 元素（5 预设 + 自定义 + 清除）共 170px，在 172px 控件列内恰好一行。

**代价**

- 文本输入不再是原生 number，浏览器自带的表单校验/移动端数字键盘需靠 `inputmode` 与钳制补足；
- 滚轮步进只在聚焦时生效，未聚焦时鼠标滚轮仍然是滚动页面（有意为之，避免误改）；
- 容量条使用 24px 紧凑规格，与面板里的 28px 主力规格并存；这是为贴合现有 22px 工具条高度，尺寸差异只允许出现在这一处。

## ADR-43 多座位块内部分隔线独立成步骤

**背景**

主席台/多座位桌把多个座位合并在一个格子里，但格子的边框是「外框」语义。此前内部座位槽的竖线来自默认网格线；一旦该块设置了显式边框，默认边框步骤整格跳过，内部竖线随之消失，5 个座位连成一片，只能靠已坐人的底色区分。若直接在显式边框里补线，又容易和相邻格的边界叠加成 2px。

**选项**

1. 在显式边框逻辑里顺带画内部竖线；
2. 在 `collectBorderLines` 中新增独立步骤，只负责多座位块的内部槽边界；
3. 在画布与导出各自画一遍。

**结论**：选 2。

- 内部竖线用 `FALLBACK`（#333333、1px），与普通网格线同色同宽；按 `cellRect` 宽度等分，位置落在座位槽边界上。
- 独立步骤不读写 `borders`，显式边框仍只负责外框，因此「设不设边框」都不影响内部分隔线。
- `resolve` 对同点位、同优先级去重，块边界与相邻格边界只保留一条，不会叠成 2px。
- 画布、`renderSeatChart` 导出与打印共用 `collectBorderLines` 的结果，不存在第三套绘制逻辑。

**代价**

- 内部分隔线是视觉补线，不进入 `sheet.borders` 数据；导出的 SVG/位图与界面一致，但数据层仍只有外框。若未来需要单独控制内部线颜色，需要把这条步骤提升为可配置项。

## ADR-44 折叠展开统一为 details.ui-fold

**背景**

快捷键、排除级别、提示三处折叠各写一套 `summary::before`：字号 12px 的文本 `›` 视觉高度只有约 7px，颜色还是 `--text-disabled`，看起来像误触杂点；规则说明则是固定显示的说明块。四处入口的点击区域、悬停反馈、旋转行为都不一致。

**选项**

1. 逐处把 `›` 字号调大；
2. 引入图标组件，在每个 summary 里手写 `<UiIcon>`；
3. 用全局 `details.ui-fold` 规格 + `::before` 矢量 mask 统一。

**结论**：选 3。

- 全局规则负责布局与交互：`display:flex; align-items:center; gap:5px; width:100%`，整行可点；hover 背景 `--bg-hover`，`focus-visible` 主色描边。
- 图标用 14×14 的 SVG mask chevron（路径视觉高约 12.25px），与 12px 正文同量级；颜色跟随 `currentColor`，不需要为每处传颜色。
- `[open]` 旋转 90° 向下，`transition: transform 160ms`，展开/收起方向明确。
- 规则说明由固定块改为默认收起的 `details.rules-help.ui-fold`，四类入口共用同一套 summary、图标与间距。

**代价**

- `::before` 是装饰性伪元素，不进入无障碍树；折叠语义仍由原生 `details/summary` 提供。
- 图标尺寸写死在全局规则里，若某处需要更大箭头，需要额外的修饰类，而不是逐处覆盖 `::before`。

**后续调整**

- 首版的 14px chevron 在「提示」等小字号场景比文字还高、笔画显粗。改为 12px 盒 + viewBox 内 12/16 绘制（视觉约 9px）、描边 1.6（等效 1.2px）、固定 `--text-secondary`、间距 4px。折叠控件是提示性元素，不应与正文争夺视觉权重。
- 随后再收窄张口：路径 `M5 2 L11 8 L5 14`（横向 6/16、纵向 12/16），视觉约 4.5×9px，接近 4×8 的细长比例；圆形线端与转角让尖端不再像笔尖。

## ADR-45 选中/活动指示层内缩，不与外框共像素

**背景**

1×5 合并主席台的右边缘在界面上看起来比其它三边粗、颜色更深。排查发现外框数据本身正确：四边各 1 条 1px `#333333`，内部 4 条竖线位置也对。问题出在 `.sg-active-cell`（2px 主色）与 `.sg-selection`（1px 主色）与块同矩形，直接压在外框上；主色带把 1px 黑线包住，肉眼就判成「外框叠成了 2px」。

**选项**

1. 保持指示层贴边，改细外框或改浅指示色；
2. 指示层整体内缩 2px，与外框之间留出间隙；
3. 选中时隐藏外框线。

**结论**：选 2。

- `selStyle` / `activeStyle` 都基于同一常量 `INDICATOR_INSET = 2`，宽高各减 4（最小 1px）；冻结区复用同一份样式，不存在两套。
- 外框仍是 1px 纯黑，选中框是独立的 2px 主色环，两者不再共用像素；打印/导出本来就不画指示层，因此不受影响。
- 隐藏指示层后的像素扫描证明四边等宽，修复后三档缩放实测四边均为 3 设备像素（3× 截图 = 1 逻辑像素）。

**代价**

- 很小的格子（小于 5px）内缩后指示环会贴近或覆盖内容中心；当前最小座位尺寸远大于此，暂不处理。

## ADR-46 区域高亮是临时视图状态，不进数据与历史

**背景**

用户希望点属性面板的区域行就能在画布上看清该区域的范围，点空白恢复。区域本身已有颜色，画布也已有区域高亮样式（区域色 55% 填充 + 主色虚线）。

**选项**

1. 把高亮写进 layout / 作为一次编辑操作（可撤销）；
2. 作为视图层的临时 `focusZoneId`，不进入数据、历史与导出；
3. 新做一套高亮配色与图例。

**结论**：选 2，并复用 3 已有的 `.sg-zone` 样式。

- `focusZoneId` 只存在 `LayoutView` 的本地 ref；切换布局时清空。
- `toggleZoneFocus` 只改这个 ref，不调用 `commit()`，所以不会产生撤销记录。
- `SheetGrid` 新增 `blank` 事件：pointerdown 落在 `.sg-space` 之外时发出，`LayoutView` 收到后清空 `focusZoneId`；该分支在选择逻辑之前返回，不触碰选区。
- `.sg-zone` 设 `pointer-events: none`，高亮层不参与命中测试，座位点击与框选不受影响。
- 导出/打印走 `renderSeatChart`，不读取 `focusZoneId`，临时高亮不会进入图片。

**代价**

- 高亮状态不持久化，切换页面或布局即消失；这是「临时查看」的预期行为。

## ADR-47 合并块的属性写入按锚点归一，区域容量与引擎同源

**背景**

区域级别规则依赖 `cell.zoneId`。合并块只有锚点格存内容，而属性面板的写入路径是 `eachCell`（跳过被覆盖格）。点在合并块第 2、3 个座位时选区只有一格覆盖格，区域归属被静默丢弃，导致区域容量为 0、级别规则失效，通用流程把不符合职级的人排上主席台。

**选项**

1. 修改 `eachCell` 全局语义，让它自动扩展到合并块；
2. 在 LayoutView 内增加选区归一辅助函数，只用于属性写入；
3. 只在 `assignZone` 单点修复。

**结论**：选 2。

- `eachSelectedCell()` 按 `anchorOf` 把选区归一为锚点并去重，`patchCell` / `patchStyle` / `assignZone` 共用；同一类「点合并块内部无效」的问题一起消除。
- 不动 `eachCell`：边框、填充、合并等命令仍按原语义只处理选区内锚点，避免行为外溢。
- 区域容量统计改用 `seatsOfSheet`（引擎同一份座位展开逻辑），合并块按座位槽计数、禁用座位不计，规则面板与排座结果不会出现两套口径。
- 座位不足的提示必须包含实际剩余数；区域 0 座时明确告知「没有任何座位」并指向布局分配，而不是笼统的「座位不足」。

**代价**

- 属性写入会把选区扩到块锚点，若一个选区只框住合并块的一角，改动仍作用于整块；这与合并块「一个整体」的语义一致。

## ADR-48 座序先从 1 号左手边起，再左右交替

**背景**

中心向外编号此前按「1 号居中 → 先右（x+） → 再左」生成，2 号落在画布右侧。用户按图面阅读时，2 号被读成在 1 号右手边，与「2 号紧邻 1 号左手边」的约定相反；同时 8px 座号在缩略图里易把 7 看成 5、5 看成 2，造成「重号」的误判。

**结论**

- `centerOutOrder` 先确定 1 号锚点，之后严格「左-右-左-右」向外，2 号永远是 1 号左侧紧邻座、3 号是右侧紧邻座；不因视角设置反转。
- 偶数座没有唯一中位，`evenCenterSide` 只决定 1 号取左中位还是右中位，2 号仍取 1 号左侧紧邻座。这样 6 座（左中位）为 4、2、1、3、5、6，（右中位）为 6、4、2、1、3、5。
- 编号与落位共用同一函数：`seatOrderMap` 的显示编号与 `arrange` 的实际座序不会分叉。禁用座位先被过滤，编号始终连续、不占号。
- 不为「疑似重号」增加去重逻辑：核对证实原图无重号，重号只可能来自座位 id 重复的数据损坏，靠编号层掩盖会误导用户。

**代价**

- 已有项目的排座结果方向整体翻转（2/3 号互换一侧），旧快照仍保留原结果；重新排座即按新口径生成。

## ADR-49 主席台与台下按「面向」分别编号

**背景**

同一套「左优先」参数同时套在主席台与台下，但两者的「左」并不是同一个方向：主席台人员面朝观众（画布下方），他们自己的左手在画布右侧；台下是观众视角，左手就在画布左侧。此前统一成「2 号在画布左侧」，主席台的实际座次就与「左为上」相反。

**结论**

- `RuleSet` 新增 `stageSide: 'left' | 'right'`，`hallOrder` 改为 `'center-left' | 'center-right' | 'left-to-right' | 'right-to-left'`；`evenCenterSide` 只保留「主席台偶数座 1 号锚点」语义。
- 编号层拆成两个显式函数，各自负责视角换算后共用底层 `centerOut`：
  - `stageOrder(seats, stageSide, evenCenterSide)`：左为上 → 2 号在画布右侧；右为上 → 镜像。
  - `hallOrder(seats, mode)`：中间左优先 → 2 号在画布左侧；中间右优先 → 镜像；另有单向两种。
- 默认值：`stageSide: 'left'`、`evenCenterSide: 'right'`、`hallOrder: 'center-left'`。
- `seatOrderMap`（显示编号）、`arrange`（实际落位）、导出 `renderSeatChart({ seatNumbers })` 共用同一套函数，导出图与画布不会分叉。
- 旧项目迁移：`hallOrder === 'center-out'` 归一为 `'center-left'`；缺 `stageSide` 补 `'left'`；已有 `evenCenterSide` 保留不动。

**代价**

- 主席台旧项目的 2/3 号会互换一侧（这是本次要求的方向修正）；台下旧项目由「center-out」迁移为「中间左优先」，行为与上一轮一致。
- 台下偶数座没有独立的 1 号锚点选项，固定取偏左中位以保证 2 号紧邻 1 号。

## ADR-50 行列结构操作改挂到行号 / 列标右键

**背景**

工具栏的「行 / 列」按钮只能相对当前选区插入或删除，操作前必须先选格；而用户的心智模型是「在坐标轴上想加一行/一列」，直接点行号、列标更自然。同时 `insertRows` / `insertCols` 在引擎里已有 50 条上限与元素锚点平移规则，UI 层一直没有一个能表达「在某一侧插入 N 条」的入口。

**结论**

- 工具栏删除「行列」分组，`SheetToolbar` 不再发 `insert-row / delete-row / insert-col / delete-col`。
- `SheetGrid` 新增 `header-context` 事件：行号 / 列标右键时先整行/整列选中，再携带 `{ x, y, axis, index }` 交给布局页；单元格右键菜单保持原样。
- 布局页根据表头坐标执行：
  - 列：左侧/右侧插入 1 列，左侧/右侧插入 N 列，删除当前列；
  - 行：上方/下方插入 1 行，上方/下方插入 N 行，删除当前行。
- N 值使用与「表格设置」同一套 `UiNumberInput`，范围 1–50（与引擎 `Math.min(count, 50)` 对齐），对话框文案写明上限。
- 插入后自动选中新插入的整行/整列；`shiftElementAnchors` 仍负责把右侧/下方元素锚点平移，规则与工具栏旧的插入完全一致。
- 删除是不可逆的结构操作，采用**二次确认**：确认框先算出目标行/列上的座位数，并扫描引用该布局的项目，列出将失去座位的已排人员；确认后先移除这些 `assignments`、把人员写入 `unassigned` 并保存项目，再执行结构删除并 toast 汇总。布局本身的删除仍可用撤销恢复，但人员座位不会随撤销自动还原，因此必须在删除前告知。

**代价**

- 删除行列现在多一步确认；无已排人员时也只是单击确认，成本可控。
- 表头右键与单元格右键存在两套入口，前者按「点中的行/列」定位，后者按当前选区定位，语义不同但各自明确。

## ADR-51 项目级「清空座位」先存快照再清空

**背景**

重排一次全体会议前，需要先把整场座位清空，让所有人在位人员回到未排座名单。此前只能逐个座位在座位详情里清空，30 人规模也要点 30 次；而清空属于整批破坏性操作，一旦误点又没有回退入口，代价很高。

**结论**

- 入口放在排座项目操作栏，紧邻「开始排座」，与「排座 / 重排」同一层级；按钮在 `assignments` 为空时置灰。
- 点击先出二次确认，文案写明项目名与将清空的座位数（`assignments.length`），并说明在位 / 请假状态与名册本身不变、清空前会自动存快照。
- 确认后执行顺序固定为**先快照、后清空**：
  1. `saveSnapshot({ label: '清空前快照', assignments: clone(当前分配) })`；
  2. `assignments = []`；
  3. `unassigned = presentMembers.map(m => m.id)`，请假人员不进入未排座名单；
  4. `status = 'draft'`、清空 `warnings`、`saveProject`、`loadSnaps()`；
  5. toast 汇总「已清空 N 个座位」。
- 只动本项目的 `assignments` / `unassigned` / `status`：名册、`rosterSnapshot`、布局、座位容量、在位 / 请假状态全部不变。
- 「只清空选中座位」不再单独加：项目页座位详情已有单座清空，布局页的多选右键没有对应的清空语义，硬加会与「删除行列」的座位修正逻辑重叠，收益低、风险高。

**代价**

- 每次清空都会新增一条快照，快照列表会变长；沿用现有快照管理（可批量删除、可一键清空）处理。
- 清空后如果用户不重排就直接导出，导出的是空座图，符合「清空」的字面语义。

## ADR-52 名册顺序是排座输入，不进快照冻结

**背景**

名册拖拽后的顺序没有影响排座：项目读取的是创建时冻结的 `rosterSnapshot`，只有走「手动更新 → 顺序调整」才可能写回；同时顺序只靠数组位置隐式表达，没有显式排序键。

**结论**

- `Member` 增加 `order` 作为名册顺序的持久化排序键。拖拽、新增、删除、导入后统一重编为 `0..n-1`；读取时若旧数据缺少 `order`，按数组位置补齐后重编，保证刷新、快照、排座读到同一顺序。
- 快照的职责收窄为**冻结人员属性与排座名单**（姓名、职级、单位、职务、顺序），排座只读快照。
- `ProjectView.runArrange()` **不再**调用任何快照同步逻辑：「开始排座」不会替你改写历史快照。
- 打开项目时同样不对齐顺序，差异会一直提示，直到用户在「手动更新」里确认或明确选择按快照排座（见 ADR-55）。
- `sortCandidates()` 的职级 → 单位 → 名单序排序中，名单序改用 `order`，作为同职级、同单位内的最终依据；职级优先与单位连续规则保持不变。

**代价**

- 快照与名册的顺序可能长期不一致，必须由用户显式确认；界面上用「名册已变化 N 项待更新」与排座前确认面板持续提示。
- 名册顺序变化不会自动重排已排好的座位，需要用户在手动更新后或确认按快照排座后再点一次「开始排座」；名册页已明确提示这一点。

## ADR-53 名册页「新建方案」改为纯图标按钮

**背景**

名册页头部同时存在文字次要按钮「新建方案」和图标按钮（重命名、删除），视觉规格不统一。

**结论**

- 「新建方案」改用 `UiIconButton` + `plus` 图标，尺寸 30×30、圆角 8px，与同排图标按钮一致。

- 同排主按钮「保存改动 / 已保存」保持文字样式；空状态的主按钮与其它页面的文字按钮不在此次范围内。

**代价**

- 纯图标按钮的可发现性依赖 `title` 悬浮提示；对高频的「新建」操作可接受，且保留 `aria-label` 供读屏使用。

## ADR-54 区域指定人员必须按排座顺序落位

**背景**

真实数据里名册已把「李」拖到第 1 位，`Member.order` 也正确持久化，但重排后 1 号位仍是「张」。项目规则中存在区域手动指定：

```json
{ "zoneId": "zone-stage", "rankIds": ["rank-1"], "memberIds": ["m-1", "m-2"] }
```

`arrange()` 的区域指定人员先于正常队列落位，原先按 `rules.zoneRules[].memberIds` 的存储顺序遍历，直接跳过了职级 → 单位 → `order` 的排序，所以 `m-1`（张）永远先占主席台 1 号位。这一路径与名册顺序、`syncRosterOrder()` 都无关，属于独立的排序旁路。

**结论**

- 区域指定人员之间也按 `remainingPool`（已排序候选池）的位置落位：`manualZones` 的 key 先按候选池索引排序，再依次找区域空位。
- 不在名单内或被锁定的指定人员仍按原逻辑跳过并给出警告。
- 座位编号与落位依旧共用 `stageOrder` / `hallOrder`：编号表的 1 号位就是第一个落位座，不存在两套遍历顺序。

**验证**

- 直接复制用户 5173 的 IndexedDB（`Trae CN/Partitions/trae-webview`）到临时配置，在真实数据上执行一次「开始排座」：
  - 打开项目即提示「1 项待更新」，手动更新中显示「顺序调整 → 按当前名册顺序（30 人）」；
  - 排座后第一排 1 号位为「李国强」、2 号为「张建国」；
  - 项目快照顺序变为「李国强#0、张建国#1」，提示清零。
- `.probe/round37.mjs` 17/17 仍通过（无区域指定的场景不受影响）。

**代价**

- 区域指定人员的落位先后由排座排序决定，而不再由规则里勾选人员的先后决定；规则编辑界面本就未承诺「勾选顺序即落位顺序」，语义更一致。

## ADR-55 排座不自动改写快照，差异先由用户确认

**背景**

此前 `runArrange()` 会在排座前调用 `syncRosterOrder()`，把当前名册顺序写回 `project.rosterSnapshot`。这会让「开始排座」变成一次隐式写入：历史快照被悄悄改写，用户没有确认路径，也失去了「项目当时用的是哪份名单」这一历史价值。

**结论**

- 删除 `syncRosterOrder()` 及「开始排座」时的自动同步；快照只在「手动更新」中由用户勾选并应用后改变。
- `runArrange()` 增加 `force` 参数：存在未确认差异（顺序、职级、单位、职务、新增、缺失）且 `force=false` 时，不排座，改为弹确认面板。
- 确认面板列出差异分类与数量，并明确两个动作：
  - 「先去手动更新」：关闭面板并直接打开差异清单，逐项确认后才写入快照；
  - 「按当前快照排座」：不改快照，`runArrange(true)` 按冻结快照继续。
- 面板文案点明「不先更新则仍按快照里的旧姓名与旧顺序排座」，避免只弹警告、没有后续路径。
- 排座本身仍只读 `project.rosterSnapshot`，结果与用户确认过的名单一致。

**代价**

- 多了一次确认步骤：有未确认差异时，「开始排座」需要用户明确选择，不能再一键完成。
- 名册改序后若直接按快照排座，1 号位仍可能是快照里的旧首位人员，这是刻意保留的历史语义。

**验证**

- 真实数据副本（快照为张#0/李#1，名册为李#0/张#1）：点「开始排座」先出确认面板，`assignments` 不变；
- 「先去手动更新」可看到「顺序调整」，应用后快照变为李#0；
- 「按当前快照排座」时 1 号位仍为张建国，快照不被改写。

## ADR-56 成员属性以快照为唯一显示源，差异检测必须覆盖全部展示字段

**背景**

用户把名册里的「李强」改成「李国强」后，「手动更新」没有识别到姓名变化：差异算法只比较单位、职级、职务、增删与顺序，**漏了姓名**。项目快照因此保留旧姓名，座位图、名单、导出全部显示旧值。这是一类「派生显示数据未随源数据更新」的问题，不能只补姓名一例。

**结论**

- `rosterDiff` 新增 `name` 差异类型，与 `unit` / `rank` / `duty` / `removed` / `added` / `order` 一起按 `DiffKind` 穷举；`applyRosterDiff` 逐项写回快照对应字段。
- 快照是成员属性的唯一显示源：`Assignment` 只存 `seatId` + `memberId`，**不冗余姓名字符串**；历史快照也只存分配，不存姓名。因此只要快照更新，所有展示位置自动同步。
- 各展示位置统一取快照，不做第二份缓存：

  | 展示位置 | 数据来源 |
  | --- | --- |
  | 座位图 / 座位详情浮层 | `rosterSnapshot.members`（`memberById` / `seatInfo`） |
  | 项目名单 / 未排座 / 请假 tab | 同上 |
  | 导出 PNG / 打印 | `displayRoster`（快照成员）+ 同一份 `seatInfo` 落位 |
  | 导出 Excel / 名单工作表 | 快照成员 |
  | 规则面板人员选择 | 快照成员 |
  | 历史快照记录 | 仅 `assignments`，姓名按当前快照解析 |

- 应用属性变更**不触碰** `assignments`，已定座位与序号保持不变；只有职级、单位、人员增删与顺序变化才提示「建议重新排座」，姓名与职务仅影响显示。
- 同一次「应用所选」会把快照的 `ranks` / `units` 定义同步为当前值，避免职级/单位名称改了但标签还是旧的。

**代价**

- 差异类型每新增一种展示字段，就必须同时补 `DiffKind`、`DIFF_META`、`DIFF_ORDER` 与 `applyRosterDiff` 四处，靠类型穷举提醒，不能再依赖临时字符串。
- 历史快照中的姓名不冻结：回退快照后看到的是当前姓名，而不是当时的姓名；这是「只存引用、不存冗余」的直接代价。

**验证**

- 5173 真实数据副本：改名、改职级、改单位、改职务各一次 → 差异清单出现 4 类共 5 项（含一条此前漏检的「李强 → 李国强」）；
- 应用后快照字段全部更新，`assignments` 签名与 1 号位不变；
- 座位图 `.sb-name`、名单 `.member-name/.member-hint/.member-duty` 同步；
- 导出 Excel 明细行同步为新姓名/职级/单位；导出 PNG 画布正常生成（与座位图同源）。

## ADR-57 差异面板用淡底色分区与聚合项折叠表达层级

**背景**

「手动更新名册」原实现用 1px 边框包住每组差异、用 `border-top` 分隔每条记录，分组与条目层级接近，长列表读起来像表格；顺序调整只给一条「与本项目快照不同」，用户看不到具体新顺序，也没有展开路径。窄视口下差异区固定 `46vh`，加上说明与页脚后容易顶出视口。

**结论**

- 分组用 `--bg-subtle` 圆角块分区，条目透明 + 圆角 hover，**不使用边框做分组/条目分隔**，与 `.insp-*` 面板的淡底色分区口径一致。
- 组头统一「图标 + 类型名 + 数量」，数量用小胶囊；条目固定「勾选框 + 姓名 + 旧值（删除线）→ 新值（主色）」三段，超长省略并用 `title` 补全，不写长句。
- 聚合类差异（顺序调整）只生成一条 `RosterDiffItem`，新增 `detail?: string[]` 承载明细；默认折叠，展开为编号姓名网格，展开后 `scrollIntoView({ block: 'nearest' })` 保证可见。
- 勾选 / 全选 / 应用分层：全选是独立胶囊按钮，页脚只有一个主按钮「应用所选（N）」；0 项时禁用，无差异时页脚只留「关闭」。
- 差异列表 `max-height: clamp(180px, 36vh, 420px)` + `overscroll-behavior: contain`；明细自身限高滚动；`<560px` 时「旧 → 新」换到第二行，保证面板始终在视口内。

**代价**

- 淡底色分区在纯白弹窗里对比度较低，靠组头字重与数量胶囊维持层级；若未来换深色主题需重新校准底色。
- `detail` 只对聚合项有意义，逐条差异不提供明细，避免把简单字段变更加噪。

**验证**

- `.probe/round41.mjs`（真实数据副本）29 项断言全通过，覆盖分组样式（border 0px / bg rgb(250,251,252)）、旧→新数量对齐、顺序折叠/展开 30 行、全选联动、1440×808 与 560×620 视口、空态与确认面板胶囊。

## ADR-58 历史快照行用两行分层，批量操作条移出滚动区

**背景**

「导出与备份」里的历史快照原本是一个单行 label：勾选框 + 时间 + 恢复挤在一起，没有标题，也看不到座位数；全选与「删除所选」和列表头混在同一行，批量操作与列表内容边界模糊。列表固定 `210px`，条目多时只能在一个没有视觉边界的区域里滚动。

**结论**

- 行固定三段：最左勾选框，中间两行信息（第一行快照标题 + 「N 座」胶囊，第二行时钟 + 时间），最右「恢复」。标题单行省略，时间与座位数不参与压缩。
- 批量操作条 `.snap-tools` 独立于 `.snap-list`，用 `--bg-subtle` 淡底色块承载「全选 / 已选 N / 删除所选」，不与列表共享滚动容器。
- 「删除所选」不是主按钮：透明底 + `--danger` 文字，禁用时弱化，hover 才用 `--danger-soft`；避免与导出按钮争夺注意力。
- 列表不使用边框分隔，行用 `radius-sm` + hover / `--primary-soft` 选中态；`max-height: min(38vh, 268px)`、`overscroll-behavior: contain`，标题省略保证窄面板（268–300px）不横向溢出。
- 删除确认继续复用 `UiModal` 与现有文案，本次只调整列表视觉。

**代价**

- 每行从 26px 提升到约 51px，同屏可见条数下降，需要滚动查看；换来标题、座位数与时间三个信息维度可读。
- `snapshots` 列表在读取时多做一次 `assignments.length` 映射，数据量小，可忽略。

**验证**

- `.probe/round42.mjs`（真实数据副本 36 条快照）21 项断言全通过：批量条在列表外且无描边、行高 51px 两行分层、无边框、选中底色 `rgb(234,241,241)`、全选/进度联动、列表内部滚动、1000px 宽无溢出、确认弹窗文案与按钮层级不变。

## ADR-59 项目覆盖层用单元格 anchor 作稳定键，布局页不再拥有区域

**背景**

区域原本挂在布局（`LayoutPackage.zones` + 单元格 `zoneId`）上，布局被多个项目复用，改一次区域会影响所有项目。同时「本次会议这个格子不坐人」是项目级临时决定，不应写回布局。需要一份项目自己的覆盖层，同时保证布局后续增删行列时引用不错位。

**结论**

- 数据模型：`Project.seatOverlay = { zones, disabledCells, cellZones, layoutPackageId?, layoutUpdatedAt? }`。`zones` 是项目独立区域定义；`disabledCells` 与 `cellZones` 的键都是单元格 anchor（该格第一个座位 id），值分别是「停用」与「区域 id」。
- 单一事实来源：`ProjectView` 的 `layout` computed 固定按 `布局 → applySeatCapacity → applySeatOverlay` 合成；排座、画布、名单、指标、导出只读合成结果。`applySeatOverlay` 每次从布局原件重算，并清除布局遗留的 `zoneId`，不做旧区域迁移。
- 旧数据：不迁移。布局里的 `zones` / `zoneId` 直接忽略；项目首次进入时 `ensureOverlay()` 补空覆盖层，旧区域规则若指向不存在的区域会被现有校验提示，不做兼容分支。
- 布局切换：保留项目区域定义，清空 `disabledCells` 与 `cellZones`（座位 id 属于旧布局），并在页面提示；写回 `layoutPackageId/layoutUpdatedAt`。
- 布局编辑：anchor 是座位 id 而非行列坐标，插入/删除行列时单元格连同 `seatIds` 一起移动，引用自然跟随；若单元格被删除，`pruneSeatOverlay` 丢弃对应停用/归属并返回清理数量，页面提示「N 项设置已失效」。新增单元格没有归属，视为未分区。
- 停用与已落座冲突：先确认，不静默丢数据；确认后按成员粒度移出分配、去重写入 `unassigned`，再记录停用；恢复只清覆盖层，不自动把人放回原座。
- 容量与停用相互独立：容量决定格内座位槽数量；停用是项目级旁路标记，不改变布局与容量，因此恢复后原容量不变。

**代价**

- anchor 依赖 `seatIds` 稳定：若未来出现「重建座位 id」的操作，需要显式重建覆盖层；当前增删行列都会保留 id。
- 布局被删除/替换后座位级设置会清空，需要用户在项目内重新框选设置。

**验证**

- `.probe/round43.mjs` 42 项断言全通过，含：停用 3 人格后容量 168→165、人员进入未排座、恢复回 168；区域多选归入与高亮；区域规则真实排座；插入行后引用仍命中、删除行后 `removedDisabled=1/removedZones=1`；导出 `hideSeats` 像素量下降。

## ADR-60 选区属性进入右侧栏，tab 标题只保留纯文字

> 座位详情卡的按钮层级已由 ADR-65 调整：锁定按钮移除，底部只保留「清空座位」。

**背景**

属性面板原本浮在画布右上，遮挡座位并挤压查看区域；右侧 tab 的「名单 28」「请假 2」「选区 2」数量角标让标题宽度跳动，视觉噪音大。座位详情卡底部「锁定座位」「清空座位」是两个同权重按钮并排，破坏性操作没有层级差。

**结论**

- 「选区」作为固定 tab 放在「概览」之后，面板内容进入侧栏滚动流；选中单元格/框选后自动切到该面板，未选中时显示「先选中单元格」空态，而不是空白面板。
- 所有右侧 tab 标题只保留纯文字：概览、选区、名单、请假、规则、导出。数量信息不塞回标题；面板内部（如「已选 N 格」、区域座位数）继续保留。
- 详情卡底部统一为 `.insp-actions` + `.insp-btn`（28px 高）：锁定为普通描边按钮，锁定时 `is-on` 用现有 primary 淡色；清空为 `is-danger` 弱危险描边并 `margin-left: auto` 右对齐。属性面板的「停用所选」同样降为 `is-danger`，与「恢复所选」形成主次。
- 不新增颜色，全部复用 `--primary-*` / `--danger-*` / `--bg-subtle` token。

**代价**

- 属性面板不再覆盖画布，设置时需要在右侧栏与画布之间移动视线；换来画布无遮挡。
- tab 去掉数量后，需要进入名单/请假页才能看到人数，列表页本身已有计数。

**验证**

- `.probe/round43.mjs`：tab 文本为 6 个纯中文标题且无 `.tab-badge`；未选中打开显示提示；详情卡底部两个 `.insp-btn` 高度均 28px，清空为 danger 且右对齐；属性面板批量停用/恢复可用。

## ADR-61 区域列表常驻，画布框选不用十字光标

**背景**

「选区」面板此前把整个内容包在「有选中」分支里，未选中时只剩一句空态提示，项目里已定义的区域看不到也点不到，必须先随便框一格才能高亮区域，与「区域是项目级配置」的心智不符。同时画布为了提示可框选，空白处与拖动中都显示 `crosshair`，视觉上像绘图工具，和页面其它位置的常规指针割裂。

**结论**

- 区域列表是项目级信息，不受选区约束：`所属区域` 小节、区域 chip、`＋ 新建区域`、`取消高亮` 始终渲染；只有批量下拉与「选区概况 / 座位容量 / 本次会议」依赖选区。
- 未选中时的空态提示收进批量属性位置（`.side-empty.is-compact`），并点明「下方区域列表仍可点击高亮」；不新增遮罩、不置底、不覆盖列表。
- 画布空白处与框选过程中的光标统一为 `default`；座位保持 `pointer`，中键平移保持 `grabbing`。只改这两处，不扩散到其它交互状态。

**代价**

- 框选不再有十字光标做可拖拽暗示，需要靠图例区「空白处拖动框选 · Ctrl 追加」文案承担提示。
- 未选中时面板同时存在「未选中」提示与可点的区域列表，信息密度略高，但区域可直接操作。

**验证**

- `.probe/round44.mjs` 13/13：无选中时区域 chip 常驻且批量下拉隐藏；清空选区后列表仍在；无选中点区域高亮成功；空白处/框选中光标 `default`，座位 `pointer`。

## ADR-62 区域高亮的层级与可见性判定

**背景**

区域高亮 `.sg-zone` 没有设置 `z-index`，在层叠顺序中落在 `.sg-overlay`（座位层，`z-index: 3`）之下。座位槽在已排座时使用近不透明的职级底色，导致高亮只在空位上可见、在已排座座位上完全被盖住。`round44` 只断言 `.sg-zone rect` 存在，DOM 有节点即通过，掩盖了这个问题。

**结论**

- `.sg-zone { z-index: 5 }`：高亮必须压在座位层与边框层之上，排座页面以「看得见」为准；布局页不使用该 prop，不受影响。
- 填充透明度 0.32 + 1.5px 虚线描边：既保证整块区域一眼可见，又不把座位姓名压到不可读。
- 以后验证画布叠加层不能只数 DOM 节点，必须做像素级或 `elementsFromPoint` 的可见性判定。
- 区域无单元格归属时不做「聚焦空区域」的静默处理，改为 `flash` 明确提示先归入单元格；chip 仍显示 `is-on` 表示当前聚焦对象。

**代价**

- 高亮填充会轻微覆盖座位文字与座位选中描边，属于临时态，取消高亮即恢复。
- 像素断言依赖固定窗口尺寸与缩放，探针需保持 `--window-size=1440,900`。

**验证**

- `.probe/round45.mjs` 14/14：真实点击 chip；有选中/无选中两种状态各对 2 个区域单元格做截图逐像素比对；再点取消、点空白取消、切到无归属区域提示、切回原区域。

## ADR-63 区域改色/改名的入口与数据边界

**背景**

区域创建后颜色固定，想区分用途只能删了重建，重建会丢归属。区域 chip 原本是单一按钮，只负责切换画布高亮，没有编辑入口；重命名入口只在排座规则面板的列表里。

**结论**

- chip 由单个按钮改为整行容器：左侧颜色点（`button.bp-zone-color`）与右侧 `✎`（`button.bp-zone-edit`）都打开同一个「编辑区域」弹窗，复用全局 `UiColorPicker` 的 5 个预设色；点名称区仍切换高亮。两者都 `@click.stop`，不影响行级高亮。
- 编辑只写 `seatOverlay.zones[].name / color`；`cellZones`、`disabledCells`、`seatCapacity` 不在编辑范围内，改色不会重算容量或丢归属。
- 高亮颜色直接取 `zone.color`：聚焦态保存后 chip 圆点与 `.sg-zone` 填充立即更新；未聚焦时保存只更新 chip，避免凭空出现高亮。
- 持久化沿用项目的 900ms 自动保存，不额外加写库接口。

**代价**

- chip 行内多两个可点区域，键盘交互需要按住 Enter/Space 作用在行上；颜色点与 ✎ 目前只支持鼠标/触屏。
- 颜色仍受 5 色预设限制，自定义颜色沿用弹窗内的取色器，不算新增颜色体系。

**验证**

- `.probe/round46.mjs` 14/14：真实点颜色点 → 5 个预设 → 保存；chip 圆点与画布填充同步；座位数/高亮格数/已排座数不变；✎ 改名生效；刷新重进项目颜色与名称保持。

## ADR-64 关于页版本号取自 package.json

**背景**

版本号若手写，容易和 `package.json`、构建产物脱节。离线单文件场景没有后端可查版本，必须在构建期内联。

**结论**

- `SettingsView.vue` 直接 `import { version } from '../../package.json'`，由 Vite 在构建时内联，页面展示与构建产物同源。
- 「关于」放在设置中心右侧卡片列，沿用 `.card` + `.settings-h2` + `.settings-sub` 分区风格，不新增导航项、不新增颜色；只补 `.about-meta` 描述列表样式。
- 邮箱用 `mailto:` 链接：离线时若不弹邮件客户端，文本仍可复制。

**代价**

- 升级版本只需改 `package.json`，但必须重新构建才会在产物中体现。

**验证**

- `.probe/round47.mjs` 7/7：真实点击设置中心，关于分区、介绍、作者、mailto、版本（0.1.0）与 `package.json` 一致，无横向溢出；构建后 `dist/index.html` 内联版本一致。

## ADR-65 座位状态是停用单元格的唯一入口，锁定座位能力移除

**背景**

「不坐人」此前分散在三处：座位图例的锁定、详情卡的锁定/恢复按钮、选区面板的「恢复所选 / 停用所选」加一段说明。同一件事有多个入口，且说明文字把操作后果写成常驻文案，挤占属性面板。锁定座位数据只影响「重新排座时保留该分配」，实际价值低，却需要额外字段、按钮、图标和换座守卫。

**结论**

- 统一用「座位状态：坐人 / 不坐人」表达单元格是否可用，语义与覆盖层 `disabledCells` 完全一致：不坐人即停用，不计入可用座位，排座、导出、打印全部跳过。
- 入口只有两处，且是同一个控件的两种场景：座位详情卡的 `.sp-state` 行，和选区面板批量属性区的「座位状态」小节。详情卡针对单格，选区面板针对当前框选；不提供第三个入口。
- 有人格切到不坐人必须先确认，确认后移除该格全部分配并将成员去重加入 `unassigned`；恢复坐人不需要确认。
- 详情卡底部动作只保留「清空座位」（`.insp-btn.is-danger`，28px），与状态行形成「状态在上、破坏性操作在下」的层级，不再并排同权重按钮。
- 删除 `Assignment.locked`、`keepLocked` 入参、锁定过滤与换座守卫、座位图锁定图标与图例、导出「锁定」列。旧项目里残留的 `locked` 字段不迁移、不读取，排座新结果不再写入该字段。
- 概览不再展示「本次停用」统计，也不换成「不坐人」等其它形式；状态行只保留项目状态与名单人数，保持原有 8px 间距与基线对齐。

**代价**

- 失去「锁定后重排仍保留」的能力；需要保留某人座位时，只能排座后手动安排或将其排除在参会名单外。
- 「不坐人」与布局的「固定空位」仍是两套来源：布局固定空位不改，详情卡不提供状态切换，需回会场布局修改；项目内停用走覆盖层，随项目保存。
- 选中格批量设为坐人时不会重新排座，只恢复可用性，人员仍在未排座名单中。

**验证**

- `.probe/round48.mjs` 32/32：概览无「本次停用」且状态行无空位、基线一致、间距 8px；排座结果字段无 `locked`；座位图无锁定图标/图例；详情卡状态行仅两项、底部仅一个危险清空按钮；有人格停用先确认并移入未排座、可用座位减少，恢复后回到原值；选区面板仅一处座位状态入口，批量往返生效。

## ADR-66 不坐人统一斜纹，三端同源

**背景**

「不坐人」此前只有文字标签与图例色点，画布、导出图片、打印各画一套；布局固定空位与项目级停用又各有一套叫法（固定空位 / 本次停用 / 不坐人）。用户明确要求不坐人就等于固定空位，只保留斜纹这一种视觉，且三种输出必须一致。

**结论**

- 视觉只用细斜纹，不写文字：画布由 `SheetCellBox` 的 `.sg-seat-cell.is-disabled` 绘制，覆盖层 `.sb-seat` 不坐人时不渲染任何子节点，`title` 仅作为无障碍提示。
- 斜纹参数统一为 45°、tile 4px/1px（画布）与 7×7 tile、0.8px 线（`renderSeatChart`），颜色全部取 `--bg-subtle` / `--border-strong` 对应的十六进制值，不新增颜色。
- 导出与打印共用 `renderSeatChart`：删除 `ChartOptions.hideSeats`，不坐人格改为画斜纹占位而不是跳过，因此 PNG 与打印纸张上的空位位置与画布完全对应。
- 选中 / 框选不坐人格时只加主色描边，背景保持透明，避免 `--primary-soft` 实心填充把斜纹糊掉。
- 术语统一为「不坐人」：图例、概览统计、座位构成、副标题、Excel、详情卡与提示语不再出现「固定空位」「本次停用」。

**代价**

- 斜纹比文字标签更依赖屏幕与打印分辨率；A4 打印时线宽固定为 1 个设备像素级别，远看仍能辨认，但极小的座位格斜纹会偏密。
- 不坐人格不再显示座号，导出布局图（`mode: 'layout'`）也不显示该格座号，与「固定空位 seatNo = 0」的既有语义一致。

**验证**

- `.probe/round49.mjs` 16/16：画布 `background-image` 含 `repeating-linear-gradient`、虚线边框保留、文本为空；选中态背景透明；图例与概览无「固定空位 / 本次停用」；`renderSeatChart` 像素采样斜纹占比 0.186、深色文字像素 0、最低亮度 231。

## ADR-67 固定座位按 seatId 绑定，排座前先占座

**背景**

会议里常有「某位领导固定坐某个位置」的硬约束。此前只能先排座再手动拖人，但重新排座会把人冲掉；也不能表达「这个人不要参与其余座位排序」。区域手动指定只能限定区域，不能精确到座位。

**选项**

1. 用单元格 anchor 作为绑定键（与 `disabledCells` / `cellZones` 一致）——双人桌无法分别固定，多人桌语义含糊；
2. 用 `seatId` 作为绑定键，固定人员先落座并移出候选池；
3. 只在排座完成后覆盖结果，不改候选池——重排后仍需再次覆盖，且固定人员可能被排到别处再被挤掉。

**结论**：选 2。

- `ProjectSeatOverlay.fixedSeats: Record<seatId, memberId>`，只存在项目里，不写回名册与布局。
- 排座开始前按座位顺序先写绑定人员并占位；这批人从候选池剔除，因此不会出现在其他座位。固定优先级高于区域手动指定、区域级别与职级分层。
- 键用座位 id：`seatIds` 随插删行列与单元格移动，绑定自动跟随；多人桌可对每个座位单独固定；座位槽被删除时由 `pruneSeatOverlay` 清理并提示。
- 绑定人员不在名册时不自动删除，保留并在规则页与排座 `warnings` 中持续提示，避免静默丢配置；绑定座位不坐人时固定暂不生效，人员回候选池按规则排序。
- UI 入口在座位详情卡：搜索名册、显示当前绑定、可解除；设置后立即落座，原固定人员/原座位人员移入未排座名单。名单行显示「固定」，规则页集中展示固定清单与所有冲突。固定座位禁止拖拽换座与清空。

**代价**

- 项目覆盖层多一份与座位 id 绑定的数据；布局大量重排后可能产生需要清理的失效引用（已提示）。
- 固定人员不参与候选池，因此可能空着更靠前的座位；这是「固定」语义的直接结果。
- 同一人手工制造多条绑定（例如直接改数据库）时只保留座位顺序第一个，其余仅在提示中体现，不自动删除。

**验证**

- `.probe/round50.mjs` 29/29：固定后立即落位、重排保持且只出现一次、剩余座位数量不变；名单/规则页标识；插行跟随、删行清理提示；七类冲突警告与正常绑定断言。
